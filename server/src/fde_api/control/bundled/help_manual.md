# FDE 工作台 · 操作使用手册

> 这份手册随仓库分发（`docs/`），同名副本烤进 API 镜像供智能助手 help_fetch 按章节检索；桌面端「使用帮助」页是它的内嵌精简版。
> 它覆盖桌面工作台里你能看到的所有模块：每个模块要干什么、点哪里、填什么、期望看到什么，以及容易卡住的坑。
> 阅读约定：`[管理]` 表示仅管理员（admin）可见/可操作；`[负责人]` 表示需你（项目负责人）或管理员。

---

## 0. 开始前：三件必查的事

桌面端能进界面，不等于后端活着。绝大多数"点了没反应 / 一直转圈"是后端没起或登录态过期。

1. **后端服务是否在跑**：桌面端连本地 Flask API（默认 `http://127.0.0.1:8010`）。
   后端没起时所有页面报"无法连接服务端"。
   起法：`docker compose up -d api worker scheduler`（见 §14 快速恢复）。
2. **后台 worker 是否在跑**：文档生成类操作（调研导出、项目计划导出、SOW 导出）都靠 worker 消费队列。
   worker 没起时，这些操作会一直停在"正在后台生成…"。
3. **登录态是否过期**：访问令牌 15 分钟过期，靠 30 天刷新令牌自动续。
   如果突然全按钮"提交后转圈又回到未提交"，先退出重新登录一次（见 §14 故障排查）。

首次登录会进"强制改密"页，改完才能看到工作台。忘了密码找管理员在"用户管理"里重置，重置后对方下次登录被强制改密。

**三件事各自的失败信号**（便于快速定位）：
- 后端没起 → 所有页面报"无法连接服务端"。
- worker 没起 → 页面正常，但导出类操作（调研结果 / 项目计划 / SOW）永远停在"正在后台生成…"。
- 登录态过期 → 全页面按钮"提交后转圈又回到未提交"。先退出登录重新登录一次。

## 1. 角色与权限（先搞清你是谁）

| 角色 | 能干什么 |
|---|---|
| admin（管理员） | 全部模块 + 系统管理（模板/文档模板/模块/用户/系统配置） |
| project_lead（项目负责人） | 名下项目的管理操作（canManage） |
| fde_engineer（工程师） | 被指派的工程任务，可填调研表 |
| viewer（查看者） | 只读。写操作按钮不渲染，只能看 |

"新建项目""导出项目计划""任务/成员/门禁编辑"需 `[管理]` 或 `[负责人]`。
"行业模板 / 文档模板 / 模块管理 / 用户管理 / 系统配置"五个页面 `[管理]` 专用，非 admin 直接访问会被打回项目页。

## 2. 项目工作台（左侧「项目」）

### 2.1 项目列表
- 登录后默认进项目列表。页头说明"查看进展与交付范围，按负责人、行业和模块定位项目"。
- 筛选区选 状态 / 负责人 / 行业 / 模块，点「应用筛选」；列表按卡片展示完成度进度条。
- 点卡片「进入项目」或「上一页/下一页」翻页（每页 20 条）。

### 2.2 新建项目（`[管理]` 或 `[负责人]`）
右上角「新建项目」→ 三种方式三选一：

1. **从模板新建**：选一个已发布的行业模板 → 走 4 步向导。
2. **上传预调研表新建**：点「上传预调研表」选 `.docx`（≤100MB），AI 解析完成后自动回填项目名、客户代号、背景、模块勾选，之后仍可人工调整。⚠️ 依赖模型服务已配置。
3. **手动新建**：4 步向导（基础信息 → 负责人 → 首期模块 → 确认创建）。

向导要点：
- **必填**只有：项目名称、客户代号、计划开始日期。项目编号、openfde engagement、fdeops 工作区都可留空（"可后补"）。
- **客户代号**格式 `客户A·行业·城市`（实名映射只在 fdeops/openfde，库里只放代号）。
- 勾选模块时若选了有前置依赖的模块，前置会自动补选并提示"已自动选择前置模块：××"；把前置取消勾选会被拦。
- 负责人下拉只对 admin 开放；项目负责人角色创建时负责人固定为自己。
- 手动创建成功后会弹窗问"是否把本次项目配置另存为新的行业模板草稿"，输入模板名保存（不填就跳过）。

## 3. 项目详情页（12 个标签页）

进项目后顶部是 12 个 tab：概览 / 任务 / 门禁 / 报价收款 / 调研 / 方案设计 / 工作流 / 术语表 / **执行事实** / 文件库 / 项目管理。支持键盘左右/Home/End 切标签，点标签跳对应 hash（如 `?tab=gates`），可书签直达。

> 键盘切标签有前提：**焦点需在标签栏上**（点一下当前标签，或用 Tab 键移进去）。在页面其他位置按方向键不起作用。Home/End 直接跳到第一个/最后一个标签。

### 3.1 概览
- 选状态下拉（状态机约束，如草稿→进行中/已取消）点「更新项目状态」；取消项目有二次危险确认。
- 点「编辑」改客户代号、SOP 节点、日期、背景后「保存」。
- 下方甘特图按工作日展示任务条与依赖线，依赖风险任务标红。
- 「导出项目计划及进度」`[管理/负责人]`：一键提交后台生成，完成后自动进文件库并保留为新版本。
  ⚠️ 前提是管理员已发布"项目计划及进度"文档模板（否则报错并指引去文档模板页发布）。

### 3.2 任务
- 「新增任务」（需 canManage）：在编辑器里填 状态/进度/工期/负责人/协作人/前置依赖。
  - 进度必须是 0–100 整数。
  - 工期必须与计划起止日期的工作日数一致，否则被拦（"计划开始日期、结束日期与工期不一致"）。
  - 阻塞状态必须写原因。
- 卡片上铅笔图标可打开完整任务编辑器。

### 3.3 门禁（重点，G1–G9，详见 §4）

### 3.4 报价收款
- **报价区**：
  - 一键「首单默认参数（轻量 / ¥150/h / ×1.0 / 冷启动锚点）」即建报价。
  - 或展开「自定义系数」选 档位（轻量25h/标准50h/旗舰80h）、锚点、时薪、数据/合规/档内偏离系数，点「按上述系数建报价」。
  - 档内偏离选 ×1.40 时，必须选 C 分支处理四选一。
- 报价卡显示公式价、锚点区间、建议报价与 claims 核验进度（accepted/total）；首单报价要回填"实际工时"做校准；成交后「回填成交价」；点「草稿」看报价计算 HTML。
- **收款区**：选 SOW 类型（B 50/50、C 40/40/20、A 预付、D 月付预付）+ 合同基数金额，点「生成收款计划」；每行可「设到期」「回填」实收金额与发票号；汇总条显示应收/已收/未收/逾期与 D7/15/30/60 催款计数。
- **合同区**：四类 SOW 卡片（只存指针，PDF 在 fdeops）：填签约日、验收窗口、账期、终止条款摘要和 `fdeops://` 指针，点「登记/更新」。

### 3.5 调研
- 左树选调研对象（企业/部门/岗位/流程/机会）。
- 写"共用备忘录"（Markdown，Ctrl/Cmd+S 保存），或点"个人备忘录"看各自笔记。
- 点调研表卡片「填写」作答，有完成度百分比。
- **事实三态流转**（已实施）：填完点「确认事实」提交；确认后要改，点「创建修订版」——
  修订版保留完整版本链，不覆盖原始记录；否决/退回走「拒绝」并写明理由。
- 「导出到文件库」后台生成 DOCX；"AI 合并整理"生成整理预览，点"采用整理结果"才写回共用备忘录。
- **填表权限**：admin、项目负责人本人、或"项目成员角色 member 且系统角色为工程师/负责人"可填；普通查看者只能看不能填。
- 未保存离开会被拦："当前表单有未保存修改，确定离开吗？"；拖排序前必须先保存（"请先保存当前未保存的内容，再调整顺序"）。

### 3.6 方案设计
- 关联 AI 机会写方案（可 AI 整理）→ 保存 → 导出 SOW 进文件库。
- 方案"弃用"要输当前账号密码确认（不是普通按钮）。
- 来源机会更新后旧文档保留快照，提示"如需纳入变化，请保存新的方案后导出 SOW"；方案弃用后不能继续导出，需先编辑保存新版本。

### 3.7 工作流

- 左侧「工作流」区块列出本项目的工作流**定义卡片**（状态：草稿 / 已发布 / 已归档 · 当前版本 · 节点数概览）。定义的新建/发布暂无人工 UI 入口（见 §12），本页只读呈现定义并控制运行。
- 下方**运行列表**显示 run 的七态：排队中 / 运行中 / 等待审批 / 已暂停 / 成功 / 失败 / 已取消，附错误摘要；列表有界，超出时明确标注 `truncated`。
- 点单条 run 展开节点树：每个节点八态（待执行 / 就绪 / 运行中 / 等待审批 / 成功 / 失败 / 已跳过 / 已取消）+ attempt 代际 + 错误信息。
- 「取消」`[管理/负责人]`：仅非终态 run 可点。对已结束的 run 再取消是**幂等语义**（返回"未取消"而不是报错）；对终态 run 直接取消会提示 409——都是正常表现，不是故障。
- 「恢复」`[管理/负责人]`：仅"失败"的 run 可恢复——失败/已跳过的节点回到待执行重投；其余状态恢复会提示不可恢复。

### 3.8 术语表

- **术语**只读清单：按规范名或别名搜索；列为 术语 / 类型 / 定义 / 状态（候选 / 已确认 / 已合并 / 已退役）/ 版本；合并后让位的名字带"（让位别名）"标记。控制台不直接改术语——候选与修订一律走变更集评审。
- **关系类型**只读卡片：全局 / 项目两种作用域，含 源 → 目标 类型约束；登记与停用走管理通道，全局行需系统运维员。
- **变更集评审**——AI 候选与人工提案的唯一落点，`草稿 → 评审中 → 已确认 / 已否决`，确认前不物化：
  - 状态过滤下拉筛五态；卡片带来源（如 `research_import:<id>`）与摘要，点开看动作明细与 base 快照指纹。
  - 草稿可「提交评审」；评审中可「确认物化」（单事务全成全败）或「否决」——**否决必须写理由**（留痕）。
  - 自己提交的变更集自己确认会被 403 拒绝（拍板人 ≠ 提交人），页面原样呈现，不是 bug。

### 3.9 执行事实（只读）
- 把项目里散落的执行痕迹汇成一条可查的事实链，回答「这事到底发生了什么」——
  比如「这个报价单是谁在什么时候改的」「上次 AI 调用用了多少 token」。
- 三源归并：**项目证据**（登记的证据实体）、**操作事件**（人做的写操作）、**AI 调用审计**（模型调用记录）。
- **维度差异**：前两类是**项目维度**；AI 调用审计是**账号维度**（无项目外键，跨项目共用同一条审计流，
  按当前账号过滤）——响应里会明示，不是数据串了。
- **不推断**：某类事实没有记录就是没有。外部操作若无真实回执，此处呈现为「无记录」，
  不会由模型自述或时间线拼装出「已完成」的语义。
- **只读**：不能在这里新增/修改/删除。补录证据走「门禁」提交流程，补录操作记录走对应模块的正常操作。

### 3.10 文件库
- 用「类型/业务阶段/状态」三个下拉筛选。
- 「上传项目文件」（≤100MB）。
- 每张卡可 下载 / 预览 / 版本 / 标记弃用 / 恢复；生成中的文档显示转圈，完成后自动刷新；失败的点「重新生成」。
- 说明：项目文件用于人工归档；调研结果、PoV、SOW 等业务文档生成后会自动进这里。

### 3.11 项目管理
- 增删成员、批量分配任务、追加/取消模板快照中的模块。

## 4. 门禁（G1–G9）详解 ★ 最常卡住的地方

状态语义照搬 SOP，每门 5 态：`待证据(pending) → 待核验(evidence) → 已过门(passed) / 有条件通过(conditional_pass，仅G9) / 未过门(failed)`。

**核心规则：`claimed ≠ accepted`。清单项在人工核验"接受"之前一律是黄标 claimed，不能算过。**

| Gate | 名称 | 清单要交什么 |
|---|---|---|
| G1 | 立项门禁 | 评分记录 |
| G2 | 需求确认 | 真需求卡（leads.md 附） |
| G3 | 诊断交付 | 诊断报告（数字全 claimed）、SOW-A 签署、A 款预付到账、数据授权书四项勾选 |
| G4 | 合同签署 | SOW-B/SOW-C、结果合同页、报价单、里程碑计划、SOW-B 签署、B 预付 50%、C 独立 SOW-C |
| G5 | 交付启动 | trust-profile/success/brief 等 .fde/ 全套 |
| G6 | 方案设计 | 问题陈述（SCQA）、基线数字、非目标清单 |
| G7 | 试点 | options 文档、success.md 定稿、Eval 计划、B 试点章程定稿 |
| G8 | 上线决策 | prototype-log、POC 验收表、business-case |
| G9 | 上线门禁 | 生产环境、Runbook、Go-Live 单、演练记录、SOW-C 里程碑（40/40/20，末款绑 G9） |

门禁与 SOP 阶段唯一对应（`server/seeds/gates.json` 的 node_key，源自《门禁与阶段唯一映射表-v1.3》）：
G1↔S1、G2↔S2、G3↔S3、G4↔S4、G5↔S5、G6↔S6、G7↔S7、G8↔S8、G9↔S10。
S9 并入 G8 前执行、S13 是 value+receipts 闸门，两者均不设 G 编号门禁。

### 操作流程（`[管理]` 或 `[负责人]`）
1. **提交证据**：状态为"待证据"或"未过门"的门，点「提交证据」。
   - 逐项填 `source_uri`（如 `fdeops://engagements/<代号>/.fde/…`）和 64 位 sha256。
   - **sha256 生成**：页面上提示用 `certutil -hashfile 文件名 SHA256` 生成（Windows），或任意 SHA256 工具。
   - **全部清单项都填完**才能点「提交证据（标 claimed）」，提交后该门转"待核验"。
2. **人工核验拍板**：状态"待核验"时点「人工核验拍板」。
   - 勾选接受（默认全不勾）——**pass 要求清单项全部勾 accepted**。
   - 选核验结论：pass / fail；**G9 可额外选 conditional_pass**。
   - **G8 且选 pass 时，必须选 proceed / pivot / stop 三态之一**。
   - 可附 500 字内拍板说明。提交后底部"事件留痕"追加一条记录。

### 为什么"全部显示未提交 / 提交后转圈圈又回去"
见 §14 故障排查第 2 条（这是认证态问题，不是门禁服务坏了——门禁服务链路实测正常）。

> 提交证据与人工核验拍板两步只能在桌面端项目详情页操作：智能助手只有只读工具 `gates_read`
> （查每门状态、拍板结论与清单核验进度），没有门禁写接口，也不应代任何一方拍板——门禁的价值就在人工核验这一步。

## 实操示例：证据文件怎么写（somwyn 样板）

每个项目的门禁证据都放在 `D:\test\FDE\engagements\fdeops\<项目代号>\.fde\gates\`——
用编辑器直接写文件，工作台只交「出处指针 + sha256」。somwyn 项目的 `.fde/gates/` 目录里已备好全套样板文件（覆盖 G1 到 G9，含 README 说明），直接照抄结构即可，不必从零想有哪些文件。

**三步流程（以 somwyn 为例）**：
1. **写文件**：进 `D:\test\FDE\engagements\fdeops\somwyn\.fde\gates\`，按 `G1-评分记录.md`、`G3-诊断报告.md` 这类命名写真实内容；
   签署扫描件/银行回单属"放置实际件"——把 PDF/图片放进本目录，说明页里写了核验点。
2. **算哈希**：在 gates 目录运行 `哈希清单.ps1`（右键"使用 PowerShell 运行"），一次列出全部文件的 sha256 与建议 URI，直接复制。
3. **工作台提交**：门禁 → 对应 G → 提交证据 → 贴 URI + 64 位哈希 → 全部清单项填完 → 提交（标 claimed）→ 有权限的人「人工核验拍板」。

**门 → 文件对照（somwyn 样板现状）**：

| 门 | 文件 |
|---|---|
| G1 / G2 | 评分记录；真需求卡（leads.md 附页） |
| G3 | 诊断报告 + SOW-A 签署件 + A 款到账回单 + 数据授权书（后三件放实际凭证） |
| G4 | SOW-B/C 草稿、结果合同页、报价单（可用工作台报价模块做底稿）、里程碑计划（可用项目计划导出）、SOW-B 签署件、B 预付 50% 回单、独立 SOW-C —— 共 7 件 |
| G5 | **不用新写**——.fde 根目录的 trust-profile / success / brief 就是全套，URI 直接指过去 |
| G6 | 问题陈述（SCQA）、基线数字、非目标清单 |
| G7 | options 文档、success 定稿确认、Eval 计划、B 试点章程（需客户书面确认） |
| G8 | prototype-log（部署日志就是现成素材）、POC 验收表、business-case |
| G9 | 生产环境说明、Runbook、Go-Live 单（客户签署件）、演练记录、SOW-C 里程碑核验（40/40/20 末款绑 G9） |

## 11. 术语速查

- **代号化（A2）**：库里只放 `客户A·行业·城市`，实名映射在 fdeops/openfde。
- **文件永远赢**：门禁/桥的证据真相在文件（.fde/、assets/），工作台只存出处指针。
- **claimed vs accepted**：claimed=已提交证据（黄标），accepted=人工核验接受（绿标）。
- **stale_version / 并发冲突**：乐观锁，冲突时报"内容已被其他人更新，请刷新后重试"。
- **变更集（change set）**：术语/关系候选的唯一入口——先提案、人工确认后才物化，防 AI 直接改知识层。
- **SOW**：工作说明书（Statement of Work）。
- **PoV**：概念验证。

## 12. 已知功能缺口（暂无前端入口）

这些能力目前只有 API，界面上没有按钮，别到处找：
- 自动任务创建——无 UI 入口（只能执行已有任务）。
- 扩展市场搜索/同步——服务在跑但页面无入口。
- 工作流**定义**的新建/发布——无人工 UI 入口（控制台只读呈现 + 运行控制；定义经 AI/自动化或 API 创建）。

另有两处是**只读**（有入口，但不支持在前端改）：
- 术语表与关系类型——只读清单，候选与修订一律走变更集评审。
- 执行事实面板——只读时间线，不支持新增/修改/删除。

## 14. 故障排查（照着顺序查，最快）

### 1. 整个工作台打不开 / "无法连接服务端"
```bash
# 起后端（WSL Ubuntu-24.04）。仓库路径用 FDE_REPO_ROOT 覆盖，换机时改这一处：
#   WSL 侧路径 = 宿主路径转 /mnt/<盘符>/...（例：D:\test\fde-workbench → /mnt/d/test/fde-workbench）
export FDE_REPO_ROOT=/mnt/d/test/fde-workbench
wsl -d Ubuntu-24.04 -- bash -lc "cd \$FDE_REPO_ROOT && docker compose up -d api worker scheduler"
# 看健康
wsl -d Ubuntu-24.04 -- docker ps --filter name=fde-workbench
# 容器里跑的是旧代码时，改过 server 源码后要重建：
wsl -d Ubuntu-24.04 -- bash -lc "cd \$FDE_REPO_ROOT && docker compose build api worker scheduler"
wsl -d Ubuntu-24.04 -- bash -lc "cd \$FDE_REPO_ROOT && docker compose up -d api worker scheduler"
wsl -d Ubuntu-24.04 -- docker exec fde-workbench-api-1 alembic upgrade head   # 迁移不会自动跑
```

### 2. 门禁 G1–G9「全部未提交 / 提交后转圈圈又回到未提交」
这不是门禁服务坏了（链路实测正常），几乎都是**登录态问题**：
1. 点右下角头像「退出」，重新登录（刷新 15 分钟访问令牌 + 30 天刷新令牌）。
2. 若登不上，确认 admin 账号密码没被重置/锁定；用"用户管理"重置后再登录。
3. 后端刚重启过、access token 失效：重新登录后再试。
4. 仍然卡：开 DevTools（桌面端一般可强制打开）看 Network，看 `/gates/<key>/evidence` 返回的是 401（认证）还是 4xx（参数）。401 基本就是重登能解。

### 3. 文档生成一直"正在后台生成"
worker 没跑。补 `docker compose up -d worker`。

### 4. 点了「导出项目计划及进度 / SOW / 调研结果」报"模板未发布"
管理员没在"文档模板"里上传并发布对应 DOCX。去 §9.2 补上再导。

### 5. "内容已被其他人更新，请刷新后重试"
乐观锁冲突。点提示里的「刷新项目 / 刷新远端版本」按钮，重做操作。

### 6. AI 功能报"AI 服务尚未配置，请联系管理员"
模型服务的 API Key 没配。管理员去 §9.5 系统配置 / §8.3 模型管理补 Key。

### 7. 集成桥一片空 / "⚠ 采集断连"
宿主计划任务（bridge-poll.mjs，每 4 小时）没跑或 WSL 服务停了。先确认宿主采集器在跑，再点「重新投影」。

### 8. 某按钮根本看不到
看你的角色（§1）。查看者大量按钮不渲染；新建项目/导出/编辑类需 admin 或项目负责人。
