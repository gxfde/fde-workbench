## 4. 沙箱基座设计（决议 D4 落地）

```
compose.yaml 增加服务：
  sandbox-runner:
    build: docker/sandbox          # 最小镜像：node/python 运行时 + agent CLI
    privileged: false
    network_mode: none             # 默认断网；由 runner 按 run 动态建白名单网络
    tmpfs: /workspace:size=512m    # 每 run 一次性 workspace
```

- **生命周期**：`SandboxHandle.create(profile)` → 每 run 独立容器（`--name agent-run-{run_id}`），CPU/内存/pids/超时由 docker resource flags 强制；`kill` 后容器销毁，tmpfs 随之回收。
- **egress**：默认 `network_mode: none`；需要外网时由 runner 创建 per-run 网络 + iptables 白名单（仅 agent 官方 API 域名解析 IP 段）；代理出口统一走宿主 `HTTP_PROXY`（可选）。
- **挂载**：只挂 `/workspace`（由服务端从 `masked_context` 渲染的只读输入 + `output_ref` 可写目录）；**绝不挂**真相层（`D:\test\FDE\…`）、`.env`、任何密钥文件；Windows 宿主经 WSL2 共享目录传递，路径由服务端换算。
- **凭据注入**：`agent_credentials` Fernet 解密后仅经 `docker exec -e` 环境变量注入该容器进程；宿主 shell 历史/日志不落明文（注入走内存管道）；run 结束凭据随容器销毁。
- **降级**：沙箱拉起失败 = 异常 A 类 → 不发起 run，走 L2 模板填空（`fallback_level=L2`），零计费。
- **gVisor**：不采用（D4）；`sandbox_profile` 字段预留 profile 切换，未来可换 runsc runtime 而不动接口。

## 5. AgentAdapter 规范（首个 = zcode，决议 D5）

```python
class AgentAdapter(Protocol):           # 架构方案 §6.2 原文为准
    agent_id: str
    kind: Literal["zcode","codex","claude_code","opencode"]
    async def run(self, ctx: AgentRunContext, sandbox: SandboxHandle) -> AgentRunResult: ...
```

- **zcode 适配器三段**：① spawn（`zcode` CLI 子进程于沙箱容器内，注入 AGENTS.md 纪律与任务书）；② 监听（stdout 结构化事件 → run 状态；心跳超时 → kill）；③ 回收（`output_ref` 目录扫描 → 逐产物 sha256 → `agent_artifacts`）。
  > **⚠️ 已登记偏差（售前方案 v1.2 §10 Q5 拍板，评估报告 D4 复核在位）**：本节 CLI 调用契约（`run` 子命令/`--task`/`--events`）与真实 zcode CLI 不符，`ZcodeAdapter` spawn 段须按 Q5 重写（`agents/adapter.py:93-104` 现状仍为未验证契约）；`--resume` 为布尔开关、会话续接未验证；DSH 不作第二家。重写与真机跑通随 **T-Z1**（PROPOSED）执行，本方案原文保留作设计意图存档。
- **首期任务白名单**：部署脚本 / 前端脚手架 / 文档类（低风险档）；`agent.code.write` 每次由蔡工显式授权（实时鉴权，权限回收即时生效）。
- **上下文渲染**（服务端负责，红线）：只写代号 + 已确认 ProblemItem（带 source_refs）+ 模板骨架 + 知识检索片段；**断言测试**：渲染产物字符串不含真实客户名/路径/凭证模式（CI gitleaks 旁再加一条脱敏断言）。

## 6. 评审会编排实现（meetings 模块）

- **状态机钩子**：worker 在 run 状态迁移点检查模板强制门（T1→plan 阶段前、T2→artifact 提交终审前、T4 按难度、T5 降级恢复）；**未满足（无对应 sealed minutes）则迁移被拒**，返回 `review_gate_open`——状态机级强制，非 prompt（U2）。
- **话轮调度**：主持人（编排中枢）按模板到场表 spawn 模块智能体/守卫/角色卡，每轮 2–4 人、总轮按 gate_tier（lite 2/std 8/full 12）；Killjoy 重复论点检测提前收题。
- **纪要收敛**：三段式（共识/分歧/待办）；守卫复核 source_refs 闭合，失败拒封存标 `degraded`；封存写 `sealed_sha256`。
- **修订回路**：agent 经 `meeting_get_minutes` 读纪要 → 会外修订产物 → 新 sha256 落库；回路 ≤2 轮，超限或存在未决分歧 → `ai_manual_handoff` 升级蔡工（U4）。
- **会中只读**：全部角色（含召集 agent）工具面只读子集；写调用一律 denied 留痕（U8/M4）。
- **降级**：智能体层不可用 → 强制门模板降级静态 checklist 交人工执行（L2 等价物），不阻塞业务（U9/M8）。

## 10. 迁移与发布纪律（每期不变式）

1. feature 分支 → fork PR → desktop/server-tests/gitleaks/pseudonymization 四 CI 全绿 → 合并 → ff 本地 main → 删分支。
2. 改 `server/` 必 `docker compose build && docker compose up -d` + `alembic upgrade head`（只 up -d 无效）。
3. 迁移只加不改：新表+新列带 down（`alembic downgrade` 可回滚到上一 head）；`tests/test_migrations.py` HEAD 常量同步。
4. 红线核查清单随 PR：真实客户名零入库（grep 断言）、`.env` 零改动提交、证据仅指针+sha256、agent 沙箱不碰真相层、`bridge-poll.mjs` 未触碰。
