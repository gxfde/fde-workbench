## 1. 实测事实（全部为 2026-11-07 真机直测，非文档转述）

### 1.1 zcode CLI 真实契约（0.17.1，修正登记原文两处过时记载）

- **启动形态**：`zcode.exe` 是 Electron 壳（裸调 `--version` 会拉起 GUI）；真 CLI = `ELECTRON_RUN_AS_NODE=1 ZCode.exe resources/glm/zcode.cjs <args>`（doctor 实测 node v24.21.0 / win32 x64 / sea: no / artifact: node-bundle）。
- **单发执行**：`-p/--prompt <text>`（无 `run` 子命令——登记原文③的「适配器按 `zcode run --task --output --events` 调用」契约错位**实测确认**）；`--mode`（build/edit/plan/yolo/guarded，`-p` 缺省 yolo）、`--cwd`、`--attach`、`--json`、`--target`。
- **会话续接（登记原文④勘误）**：`--resume <sessionId>`（0.17.1 **是取值开关**，非登记所记布尔开关）+ `-c/--continue`（续最近会话）。**实测验证**：`-p "只回复两个字：收到" --json` 得 `sess_abbc2b87-…`；`--resume <同 id> -p "我上一句让你回复什么？"` 同 sessionId 返回「收到」（上下文确实携带，非幻觉——新会话无从得知）。⇒ **「会话续接未验证」状态解除**，B#2 repair 增强档的降级默认可重估（另行评审，本文不预支）。
- **`--json` 载荷形状（登记原文⑤实测闭合）**：`-p --json` 输出**单对象汇总**（非 ndjson 事件流）：`{sessionId, traceId, turnId, response, usage{provider/modelRequestCount/inputTokens/outputTokens/cacheReadTokens/…}, eventCount, projection{status/turnCount/totalTokenCount/contextUsed/contextWindow}}`。粒度事件流不在 `--json` 里——在 `app-server`（stdio ZCode Protocol）模式。**适配器含义**：单发 run 用 `--json` 拿终态+用量即够；逐事件流式只有 app-server 一条路。
- 实测样本：`D:\test\FDE\tz1-probe\run1.json` / `run2.json`（648B 汇总 ×2，含完整 usage），事件流夹具据此可回放（B#14 组织方式，纯函数决策部分不在本条范围）。

### 1.2 容器内直跑实验（登记原文「必做项」的裁定证据）

| # | 实验 | 结果 |
|---|---|---|
| E1 | sandbox-runner 镜像内 `node --version` | v20.19.2（Debian 13） |
| E2 | 挂载 zcode.cjs → 容器 node 直跑 `--version` | **失败**：`ERR_UNKNOWN_BUILTIN_MODULE: node:sqlite`（zcode.cjs 依赖 node ≥22.5 内建 sqlite；镜像 node 20 无） |
| E3 | node:24-alpine 容器同实验 | **成功**：`--version` 输出 0.17.1 ⇒ JS bundle 平台无关，**node 版本是 JS 层唯一硬阻断** |
| E4 | 基线事实复核 | sandbox `network_mode: none` ⇒ 模型 API egress 为零；容器内无 provider 配置（宿主 `D:/config/provider/` 与镜像内 `resources/config/provider/` 均缺）且无登录态 |

**容器内直连路线的完整阻断清单**（任一不解决即不可用）：① node ≥22.5（可修：sandbox-runner Dockerfile 换 base 或注入 node 24——E3 已证 JS 层可跑）；② provider 配置注入（zcode-builtin.json 部署进容器约定路径）；③ 登录态/API key 注入（容器内无凭据）；④ **网络 egress 通道**（`network_mode: none` 是沙箱红线基线，放开=安全面变更）。四项全是 sandbox 基座变更，且③④触及凭据与网络两条安全边界。

## 2. 执行通道裁定提案（交蔡工拍板，不代决）

| 通道 | 形态 | 与实测的相容性 | 代价/前置 |
|---|---|---|---|
| **A. 宿主侧 zcode 代理（推荐）** | Windows 宿主跑一个只读受控代理进程（沿 bridge-poll 宿主纪律同构）：工作台 API 落 run 请求 → 宿主代理 spawn `zcode -p --json --cwd <workspace>` → 回传汇总 JSON+产物指针 | ✅ 与全部实测相容：宿主 Electron 现成、`--json` 终态+usage 齐备、`--resume` 已验证、**零 sandbox 基座变更** | 须扩「通道授权」并修 AGENTS.md「bridge 只读」红线（新增宿主写通道）；代理进程管理/存活监控；商用条款确认（§1.3） |
| B. openfde 加 zcode executor | 在 openfde 宿主采集器上加执行通道 | ⚠️ 与 A 同为宿主侧（容器路线已被 E2-E4 否决），但叠加 openfde 依赖 | 除 A 的全部前置外，**须按 B#35 登记 openfde 版本/许可/快照日期**（MIT，HEAD a54be6c 2026-10-27；当前未登记）+ 许可混置 legacy/ 逐件核 |
| C. 容器内直连 | sandbox-runner 内跑 zcode | ❌ E2-E4：四重阻断全在沙箱红线面上 | node 升级+凭据注入+egress 放开——三项安全面变更叠加，**不建议** |

**推荐 = A**：最小安全面（零沙箱基座变更）、与 bridge-poll 宿主纪律同构、`--json`/`--resume` 实测契约齐备；B 作为 A 落地后的可选演进（届时补 B#35 登记）。**无论 A/B，均须先办两件事**：① AGENTS.md「bridge 只读」红线修订（新通道授权，显式拍板）；② zcode 商用条款确认。**两件未办结前，编码执行通道维持现状**（`ZcodeAdapter` 的 `zcode run --task` 虚构契约不修即维持 `adapter_missing` 降级——登记闸③「不阻塞第一阶段主线」原样生效）。适配器 CLI 段重写（`-p --json --cwd` 真实形态）随通道拍板后的实施轮执行，本文不预改代码。
