# 自动化运行场景：zcode / codex 能否替代 DSH，以及仅装 DSH CLI 是否足够

> 评估日期：2026-11-05　｜　对象：fde-v3（Workbench V3）　｜　目标语境：将蔡工 FDE 尽可能实现智能化与自动化
> 性质：**只读评估轮**，零代码、零配置、零依赖安装。沿用 `docs/audit/agnes-harness-融合评估-2026-11-05.md` 的口径：证据锚点、假设单列、不把推测当事实、不预设任一方案必然可行。
> 用户原文写作「DHS cli」，本报告按项目内统一缩写 **DSH**（DeepSeek Harness）理解；若所指为另一系统，§12 前提 1 需重确认。

---

## 0. 结论摘要（先给裁决）

| 判断项 | 结论 | 一句话依据 |
|---|---|---|
| **仅安装 DSH CLI 是否足以实现自动化运行** | **不足以** | 项目客户端连的是 HTTP 8020 上的 FDE 自定协议 `fde-dsh-v1`；官方 CLI 只有一次性 `headless`、stdio JSON-RPC（`sdk`/`acp`）与回环 Web UI（3080），**不提供 `/v1/executions` 与 FDE 回调** |
| **zcode 能否替代 DSH** | **不能直接替代** | 已接入的是另一条轨：人工授权触发、沙箱内 CLI、产出文件；与 `control/` 自动化轨**零交叉引用**，且本机沙箱/CLI 均未就绪 |
| **codex 能否替代 DSH** | **不能直接替代（且当前不可用）** | 本机 CLI 已装，但项目**只有 `ZcodeAdapter` 一个实现**，`service.py:182` 对非 zcode 一律判 `adapter_missing` |
| **是否所有环节都非 DSH 不可** | **否** | MCP 工具执行在 FDE 服务端且只认自签 JWT、不认调用方；workflow / scheduler / 文档生成 / 翻译 / 门禁候选已自动化且不依赖 DSH |
| **「尽可能自动化」的真瓶颈** | **不是 DSH，是人工拍板红线** | 门禁、signoff、证据登记、agents 发起/接管/重试、评审收敛均为人工授权写路径，AI 不得代执行 |
| **推荐** | **P0 维持现状 + 先澄清诉求；P1 若要无人值守，做协议适配层而非换 Agent；P2 才考虑把 zcode/codex 作为编程类后端** | 成本、治理冲突与红线三重约束 |

**必须先说的现实状态**：本机 **DSH 未装**（8020 无监听、无 `dsh` 命令、compose 无服务）、**zcode 沙箱未启**（`sandbox-runner` 在 `profiles:["sandbox"]`，`docker ps -a` 无容器）、**zcode CLI 未钉定**（`docker/sandbox/Dockerfile` 只装 python+nodejs+iptables，注释明写版本钉定属试点前人工项）、**`agent_pilot_enabled=False`**。因此本轮任何方案都**尚未在本机跑通**，可行性判断只到「结构与契约层」，不到「已验证可运行」。

## 1. 分析基准：先把「自动化运行」拆成四种语义

用户目标中的「自动化运行」在本仓库对应四条互不等价的链路，混淆它们会直接导致错误结论：

| # | 链路 | 触发方式 | 执行体 | 当前是否依赖 DSH |
|---|---|---|---|---|
| A | **定时/事件自动化任务** `automation_tasks` → `automation.execute` | scheduler cron / once / interval / event，无人值守 | `dsh_runtime.current.execute` | **硬依赖**（`automation_jobs.py:90` 无 fallback） |
| B | **AI 聊天的工具调用** `/api/v1/ai/chat/messages` | 人工发消息 | `execute_ai_prompt` + MCP 回环 | 部分：无 DSH 时降级为 13 个只读工具 |
| C | **确定性工作流** `workflow_definitions` / skill 节点 | workflow run 驱动 | `execute_ai_prompt(use_tools=False)` | **不依赖**（无 DSH 走直连降级） |
| D | **编程智能体派单** `agents` / `AgentRun` | **人工 POST 授权** | `ZcodeAdapter` + 沙箱 CLI | **完全不依赖** |

另有大量后台自动化（文档生成、文件扫描/预览、翻译、调研导出）走 `outbox_events` + `worker`，同样不依赖 DSH（`jobs/handlers.py`）。**「把 FDE 尽可能自动化」的主体其实已在 C/D/后台链路里，DSH 只占 A 与 B 的一部分。**

## 2. 事实基线：两条执行轨零交叉

- `control/`：`dsh_runtime.py`、`automation_jobs.py`、`scheduler.py`、`ai_server_client.py`、`routes.py` 的 `/internal/dsh/...` 回调、`mcp_gateway.py`。
- `agents/`：`adapter.py`（`ZcodeAdapter`）、`service.py`、`sandbox.py`、`models.py`、`routes.py`。
- **双向 grep 结果：`server/src/fde_api/control/` 中零处 `from fde_api.agents` / `AgentRun`；`workflows/executor.py` 只 import `DSHRuntimeError` 做错误分类，并调用 `execute_ai_prompt`。** 即两轨**没有任何接线**。
- 技术实施方案 §5 定义 `AgentAdapter` kind 为 `zcode|codex|claude_code|opencode`，但注释明写「首个 = zcode」；`agents/models.py:38` 的 CHECK 另含 `persona`（不可执行）。`agents/service.py:182`：`if agent.kind != "zcode" or agent.kind not in ADAPTER_KINDS:` → 判 `adapter_missing`。**codex/claude_code/opencode 目前只是注册表占位。**
- `agents/routes.py:4` 原文：`POST run / handoff / retry / rehearse / recover 属人工授权写路径——AI 不得代发起、代接管、代重试`；`api_catalog.py:96` 只收 4 条只读。这是与 A 轨「无人值守」最本质的语义冲突。

## 3. 四种候选的能力边界对比

| 维度 | zcode（项目已接） | codex（本机已装） | 仅 DSH CLI | 完整 DSH 适配层 |
|---|---|---|---|---|
| 形态 | 沙箱容器内 CLI 子进程 | 本机/容器内非交互 CLI | 一次性进程 / stdio / 回环 UI | 常驻 HTTP 服务 |
| 启动参数 | `zcode run --task … --output … --events ndjson`（`adapter.py:88`） | `codex exec [PROMPT]`、`resume`、`fork`、`review`、`codex mcp add` | `dsh headless "task"` / `dsh sdk` / `dsh acp` / `dsh web` | FDE 自定 `/v1/health`、`/v1/executions`、`/v1/executions/{id}/progress`、`/v1/plugins/apply` |
| 输出 | `output/manifest.json` → code/doc/diff/config + sha256 | 文本 / 补丁 / 审查结论 | stdout 文本或 `--json` NDJSON 事件 | 结构化 `{status, execution_id, output, summary, runtime_version}` |
| 会话 | 无 session；`retry_of` 是同族重试非续接 | `resume` / `fork` 有会话 | `--session-id` 可续接 | 外部执行会话 + `external_execution_id` 回调 |
| 工具面 | 本地白名单 `effective_run_tools`，越权 `denied` 标降级 | 可配 MCP server（`codex mcp add`） | 插件体系（`dsh-plugin`） | **MCP 回环** `mcp:{url,token}` → `/api/v1/internal/ai/mcp` |
| 熔断/降级 | 超时、成本、egress deny、L0–L3、产物门 | 三档 sandbox（read-only / workspace-write / danger-full-access） | 权限预设 + `--approval-policy ask\|never` | `DEGRADABLE_DSH_CODES` 白名单降级（不含 conflict） |
| 审批 | 无外部审批回调；L3 转人工 | 无 | 无 FDE 审批回调 | `/internal/dsh/executions/{run}/approvals`（15min + sha256 + 密码确认） |
| 定时触发 | **无** | **无** | **无**（`headless` 一次任务即退出） | 由 FDE scheduler 触发 |
| 与 `fde-dsh-v1` 兼容 | 否 | 否 | **否** | 是（但需实现） |

**官方 DSH CLI 的硬事实**（`docs/cli-help.md`，2026-11-05 取）：`headless` = "Answer one task and exit"；`sdk` / `sdk-minimal` / `acp` 均为 **stdio JSON-RPC**；`web` = 回环浏览器 UI（默认 3080，`--host` 拒绝通配地址，`--trusted-host` + launch token + 签名 cookie 组成 browser-trust fence）。**没有任何 `/v1/executions` REST 端点。**

**Python SDK 是唯一可缩短适配路径的官方能力**（`docs/user/guide/python-sdk.md`）：`DeepSeekHarness(...).run(task, session_id=...)` 在进程内 lazily 拉起 `dsh --profile sdk-minimal`；明确支持 **Windows x64**、Python ≥3.10、无需系统 Node.js（wheel 内含 native runtime）；要求隔离 workspace + 隔离 `DSH_HOME`。但它是**进程内 SDK，不是网络服务**，仍需 FDE 自己包一层 HTTP 适配。

## 4. 依赖条件与权限要求

### 4.1 依赖条件

| 候选 | 硬依赖 | 本机/仓库现状 |
|---|---|---|
| zcode | sandbox 镜像与 `agent-run-{id}` 独立容器、CLI 版本钉定、真实凭据联调、iptables 生效性、`agent_pilot_enabled` | `sandbox-runner` 在 `profiles:["sandbox"]` 默认不启；`docker ps -a` 无该容器；Dockerfile **未装 zcode CLI**；Windows PATH 无 `zcode`；台账 §541/§569/§632/§646 均把联调列为**蔡工人工挂账**；`config.py:132` 试点开关 False |
| codex | `CodexAdapter`（不存在）、注册表启用、凭据、沙箱、模型合规 | 本机 `codex-cli 0.162.0` 已装；`ZcodeAdapter` 的 `spawn_argv` 与 codex 参数格式不兼容；`service.py:182` 判 `adapter_missing` |
| 仅 DSH CLI | Node（web 路径）或 Python ≥3.10 + wheel；DeepSeek 兼容端点与凭据；隔离 workspace + `DSH_HOME`；profile/插件 | 本机 Node v22.22.2 / npm 10.9.7 具备；**`dsh` 命令不存在**；`FDE_DSH_*` 未配置 |
| 完整适配层 | 上述全部 + 自研 HTTP 服务 + service token + 回调 + 版本钉定 + 安全验收 | **全机 grep 未发现 `fde-dsh-v1` 服务端实现**；`compose.yaml` 只有 redis/api/worker/scheduler/sandbox-runner |

### 4.2 权限要求（全部在 FDE 服务端，与选哪个 Agent 无关）

- **MCP 工具**：`issue_mcp_token`（`mcp_gateway.py:54`）签发 15min HS256 JWT，claims 含 `sub/ver/project_id/execution_id/capabilities`，`iss=fde-ai-tools`、`aud=fde-mcp`；`/mcp` 端点（`mcp_gateway.py:257`）是**标准 JSON-RPC 2.0**，`_identity` 只校验 token + 实时 `effective_ai_access` 与 `auth_version`，**不校验调用方是不是 DSH**。写类工具另需密码确认流。
- **DSH 回调**：`/internal/dsh/...`（`routes.py:323-383`）用 `verify_service_token`（HMAC `compare_digest`）校验 `FDE_DSH_SERVICE_TOKEN`，与 MCP token 是两套。
- **自动化**：派发时逐 `requested_capabilities` 复查 `authorize_ai_capability`；审批 15min + `arguments_sha256` + 执行前再次鉴权 + 硬白名单（仅 `task.batch_assign` / `project_tasks.batch_assign`）。
- **agents**：`start_run` 实时鉴权 + 幂等键 + 月度/单 run 预算闸 + 脱敏上下文渲染 + `agent_artifacts.reviewed` 默认值不入终审。

> **关键推论**：换 Agent **不会绕过也不会自动获得**这些权限；它们是 FDE 服务端的可复用契约。这也是「适配层」比「换运行时」更省改造的根因。

## 5. 与现有流程的兼容性：DSH 到底占多少

**已自动化且完全不依赖 DSH**（证据见 §1/§2）：workflow 定义与 skill 节点、scheduler + outbox + worker（文档生成/翻译/文件扫描/预览/调研导出）、G1–G9 证据候选与拍板 UI、派单 8 态机、agents 编程派单、门禁证据指针登记。

**依赖或退化于 DSH 的仅三类**（沿用 `docs/audit` 前序结论）：

| 环节 | 无 DSH 时 | 是否真「离不开」 |
|---|---|---|
| `automation.execute`（A 轨） | `dsh_not_enabled` → run failed（`automation_jobs.py:90` 直调，无 fallback） | **是，在当前代码结构下** |
| AI 聊天的写工具（B 轨） | 降级 `READ_ONLY_TOOLS` 13 个只读工具，`degraded=true` / `tools_available=false` 诚实显示 | 否，有已验证降级路径 |
| 插件 apply / DSH health（`/v1/plugins/apply`、`routes.py:318`） | 不可用 | 否，非核心交付链 |

**DSH 真正专属的语义**：外部执行会话 + `external_execution_id`、`runtime_version`/`agent_profile_version` 随 run 冻结（`control/service.py`）、events/knowledge/approvals 三类回调、MCP 回环 token 注入、`Idempotency-Key` 幂等。**这些不是「模型能力」，是编排协议。**

## 6. 明确分工：哪些仍离不开 DSH，哪些可由其他工具承担

### 6.1 仍离不开「DSH 位」（不是离不开某个厂商产品）的环节

1. **定时/事件无人值守执行的编排会话**：A 轨目前只认 `dsh_runtime.execute`。要换，必须改 `automation_jobs.py` 或提供等价协议的后端。
2. **审批/事件/知识三类回调**：`routes.py:323-383` 的路径与 service token 契约是 FDE 侧事实，任何替代后端都得实现。
3. **版本冻结与溯源**：`automation_task_runs.dsh_runtime_version` 落库，换后端会改变溯源语义。
4. **MCP 写工具的角色链**：虽端点通用，但签发 token 并把 `mcp:{url,token}` 注入执行体的逻辑只在 `execute_ai_prompt`（`ai_server_client.py:168-176`）。

### 6.2 可由其他工具承担（或已经承担）的环节

| 环节 | 承担者 | 依据 |
|---|---|---|
| 代码/文档/diff 生成 | zcode（已接）、codex（需补适配器） | `agents/adapter.py`、`agents/service.py` |
| 确定性文本变换 / skill 节点 | 直连 DeepSeek/MiniMax | `workflows/executor.py:880-955` 调 `execute_ai_prompt(use_tools=False)`，无 DSH 时降级 |
| 只读工具查询 | 任意能配 MCP server 的 Agent | `/mcp` 只认 JWT，不认调用方（`mcp_gateway.py:257`） |
| 定时调度、幂等、预算、产物指纹、降级 | FDE 自有 scheduler / outbox / agents 基座 | `jobs/`、`agents/service.py` |
| 一次性 headless 任务执行 | DSH `headless`、codex `exec` 均可（但都需外壳封装） | 官方 cli-help；本机 `codex exec --help` |

## 7. 改造影响与冲突点

| 方案 | 需改动处 | 量级 | 冲突 |

## 9. 主要限制与风险

1. **上游成熟度**：DSH 为 developer preview，README 明示 `THERE WILL BE COMPATIBILITY-BREAKING CHANGES`；`SAFETY.md` 明示未经安全审计、可执行模型生成代码/加载第三方插件、建议一次性 VM/容器。运行期版本随 run 冻结，破坏性变更会直接污染溯源。
2. **官方 SDK 的两个红线级默认值**：`sdk-minimal` **pins `danger-full-access`**（shell 可改任何可见路径）；`session-log-deepseek` **默认上传未接受的日志事件**（≤8 MiB/请求）。若接客户资料，必须显式 patch 关闭并使用一次性 workspace/home。
3. **客户资料红线**：证据只存 `source_uri`+sha256、真实资料不出本机；境外 CLI（codex / Claude Code）与会话日志外传均与之张力明显，境内模型约束尚未拍板。
4. **治理风险**：任何「更自动」的改动都可能诱导绕过人工拍板（门禁、signoff、证据登记、agents 发起/接管/重试、评审收敛）。这是设计红线，不是待优化项。
5. **现实未就绪**：DSH 未装、沙箱未启、zcode CLI 未钉定、真实凭据未联调、试点开关 False、台账四项均为人工挂账 → **本轮结论不可解读为「任一方案已验证可跑」**。
6. **成熟度反差**：官方 `web` 是带 launch token + host fence 的**浏览器应用**，不是给后端调用的执行 API；若有人用 `/api` 硬接，等于把浏览器信任模型当服务鉴权用，方向性错误。

## 10. 推荐方案（分层，按前置条件递进）

- **P0（零改造，建议先做）**：维持 `FDE_DSH_ENABLED=false`。把「尽可能自动化」落到**已有的** workflow、outbox/worker、直连降级、人工触发 agents 与门禁候选链；先由用户明确具体要自动化的环节（§12 前提 1）。**不安装任何东西、不开第二实施线。**
- **P1（若确需 A 轨无人值守）**：**做协议适配层，而不是换 Agent**。保持 `fde-dsh-v1` 契约不变，后端可选 DSH Python SDK（`sdk-minimal` 进程内）或自研；必须同时满足：关 `session-log-deepseek`、隔离 workspace/`DSH_HOME`、pin 版本、service token 与回调全链验收、MCP token 15min 与 `auth_version` 撤销回归。此路径对现有流程兼容性最好，但仍属新服务，需按 goal 循环立项。
- **P2（若要引入 zcode/codex 作为执行后端）**：先补全 `AgentAdapter` 分发与 `CodexAdapter`、钉定沙箱镜像内 CLI、跑完 iptables + 真实凭据联调、开试点开关；**仅用于编程/文档/diff 生成类任务**，不接 MCP 写工具、不碰审批、不代拍板。
- **P3（不建议）**：把 `automation.execute` 直接改接 agents 轨。除非先修改治理口径并单独立项，否则收益小于红线损失。
- **明确不做**：只装 CLI 就打开 `FDE_DSH_ENABLED`；用 DSH `web /api` 冒充执行 API；把无人值守自动执行引入门禁/signoff 链路。
