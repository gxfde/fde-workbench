## 2. 发现并消解的部署态真缺陷

### ★文档模板缺口（本轮真发现，堵死交付件段）

- **症状**：建项目文档 422 `document_template_not_published`；`document_templates` 表 0 行。
- **根因**：`server/Dockerfile` **未 COPY `resources/`**（只 COPY src/migrations/seeds/load_seeds.py 等），compose 也未挂载 ⇒ 容器内 `/app/resources/document-templates` 不存在 ⇒ `flask seed-document-templates` 全部 missing ⇒ 部署态模板恒空。而本仓 `resources/document-templates/` 有 **18 个已跟踪 DOCX**（仓库里有、镜像里没有）。
- **连锁影响**：文档型封包（须 confirmed 文档版）与文件型封包（须 available+sha256 文件版）双双无上游——唯一能同时产出两者的 `create_direct_file_version`（manual 修订路径）也依赖文档行存在。**即：部署态下「结项交付包」整段不可用**。此前 somwyn 十步未触此段，故未暴露。
- **本轮消解**：宿主 venv 直连活库跑幂等种子（与 `flask seed-document-templates` 同一函数，资源目录指向宿主仓库），**17 类模板全部 published、0 missing**（`created=17 skipped=0 missing=0`）。
- **修复项（挂账，建议随下轮 PR）**：~~`server/Dockerfile` 增加 `COPY resources ./resources`（一行），或 compose 挂载 `./resources:/app/resources:ro`＋部署后跑一次 seed CLI。否则**换机重建/远端部署后该缺陷复现**。~~ **【已随本轮 PR 修复，2026-11-17】**——`COPY` 方案不可行（compose build context=`./server` 不含仓库根 `resources/`），落地方案＝compose 三服务（api/worker/scheduler）只读挂载 `./resources:/app/resources:ro` ＋ `FDE_DOCUMENT_TEMPLATE_DIR=/app/resources/document-templates`（worker 需要模板字节：document.generate fallback 读盘）＋ README「迁移与初始化」节补 `seed-document-templates` 步骤。
