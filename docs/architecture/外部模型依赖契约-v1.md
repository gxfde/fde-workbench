> **来源与边界**：借鉴登记 **B#10**（见 `docs/implementation/v3-backlog.md`「开源借鉴清单登记」段）。设计原则来自 GIIP「外部模型阶段插入的设计规则」这一**抽象方法论**，以及我方既有的静默降级反证（W-8「断链不静默 done」）与 DSH 降级链现状。**按 `AGENTS.md` 红线第 8 条：只取抽象原则，不复制上游正文段落、不复制其结构化表达（表格骨架、案例叙述、措辞均为我方独立重写）；用例与判据全部依据我方真实代码核实。**
> **适用范围**：我方在确定性规则/本地逻辑之后，**新增或接入**任一外部模型（DeepSeek／Kimi／DSH 适配层／未来新增 AI 网关）作为「判定的一个阶段」时的强制约定。**不是**对既有调用链的整改清单。

## 2. 七条强制规则（我方版）

> 编号 `M-1`–`M-7` 为**我方自定义编号**，用于本文件与后续 PR 引用；与任何上游编号体系无关。

### M-1 开关默认 OFF，且关闭时行为与现状逐字一致

任何新增的外部模型阶段**必须**有一个默认关闭的开关（沿用我方 `dsh_enabled` 形态：配置项 + 布尔 + 显式默认值）。

- 关闭状态下，**该阶段完全不参与判定**，最终结果与「没有这个阶段时」**逐字一致**；
- 关闭状态下**不产生任何外部请求**（这是可断言的硬判据，见 §4）；
- 开关值**在调用时点读取**，不得在模块加载时固化为常量（模块加载时固化 ⇒ 改配置需重启，且测试无法覆盖开关的两种取值）。

**我方现状**：DSH 主路径已符合（`dsh_enabled` 默认 `False`，`config.py:70`）。

### M-2 阈值是「建议值」，不是判定常数

外部模型相关的任何阈值（置信度、相似度、最大重试、token 预算、拒绝字数等）必须：

- 标注为**建议值**（文档、代码注释、日志三处口径一致），**不得**表述为「已确认/精确/保证」；
- 数值**在调用时点读取**（配置或环境变量），**不得**在模块加载时固化为常量；
- 允许被环境变量覆盖，且**覆盖后无需重启即可生效**；
- 当阈值参与对外呈现（门禁 exit_condition、报表、SOP）时，**必须标注其性质为建议值**，否则会把「建议」变成「事实」。

> **交叉纪律**：本条与《交付效果评测协议 v0》的「上游阈值仅参考、实施前须用我方数据校准」是同一条纪律的两个面——**凡引入外部判据，必标性质**。

### M-3 失败不是错误，是「下一阶段」

外部模型阶段的失败、不可用、响应不可解析、置信度不足，**一律不是终态错误**，而是**把判定交给下一个阶段**。

- 新阶段**不得**取代既有路径——它是**插入**的一条腿；
- 新阶段失败时，既有路径**必须原样继续**（不得因新阶段存在而改变既有判定结果）；
- 但**「交给下一阶段」不等于「静默」**：失败的**事实必须留痕**（见 M-6），且**不得**把失败伪装成成功。

**我方现状与红线**：既有派单引擎的 W-8「断链不静默 done」是同一原则的另一面——**节点失败 ⇒ run failed**，即「失败」在**流程层**必须显性化。两者的分工：本条管**判定层**（新阶段失败→降级到下一阶段），W-8 管**流程层**（真失败→显性失败），**二者不得互相抵消**。

### M-4 传输层可注入，测试网络零依赖

外部调用必须经**可注入的传输层**，使得回归测试能在**网络零调用**的条件下跑通。

- 传输函数可替换（注入或替换），默认实现才走真实网络；
- **接入地址与密钥不得硬编码**，只允许经环境变量/配置项进入；
- 客户端**不得擅自裁剪请求体**——长度限制是服务端规约，客户端私自截断会导致「服务端看到的」与「本地记录的」不一致。

**我方现状**：外部模型客户端已按「主路径（DSH）＋ 降级直连腿」两段分离，测试可分别注入。

### M-5 外部响应不当作完整值：缺字段取保守值，不推测

外部模型的响应**不得**被当作完整可信值。

- 响应缺字段时**不得推测补齐**，取**保守值**（0／失败／缺省）；
- 枚举型字段出现**表外取值**时，**不修正、不改写、不猜测意图**，只留痕不参与判定；
- 非有限数值（如 `NaN`／`Infinity`）与缺失同义处理；
- **保守值的选择必须使判定流向「更保守的一侧」**（例：把不确定判为「不需要改写」而非「需要改写」），并在文档中写明该方向。

> **推论**：外部模型**不得**成为唯一权威——凡由外部模型单独决定的结论，必须可被人工复核覆盖（我方门禁体系的人工拍板优先）。

### M-6 日志只记哈希与长度，原文不入日志

判定日志**不得**记录外部响应的原文或提示词原文。

- 只留**内容哈希**（建议 sha256 前若干位）＋**长度**；
- **必须**记录「**哪个阶段作出了判定**」这一来源标记（source）——否则事后无法据日志回溯该调哪个阈值来调优；
- **不新建存储**（不新建日志表、不新建文件），沿用既有审计设施；
- 客户资料红线优先：任何原文都不得进日志、不得进 DB、不得进 git（`AGENTS.md` 红线第 2 条）。

**我方现状**：AI 调用审计走既有 `ai_call_audits`（`ai/auditing.py`），记账腿记用量与结果、不记原文。

### M-7 调用方签名不被破坏，新参数只能是可选项

新增能力**不得**破坏既有调用方的签名。

- 新增参数**一律可选**（有默认值、可省略）；
- 既有调用点**不强制改动**；
- 既有调用方的**前置判断顺序不得被新阶段改变**（例：用户显式意图的预判必须仍在模型判定之前，模型不得翻转显式意图）。

## 4. 可断言判据（供未来 PR 自查）

| 判据 | 断言方式 | 期望 |
|---|---|---|
| 开关关闭 ⇒ 零外部请求 | 注入计数传输层，断言调用数 = 0 | 硬判据 |
| 开关关闭 ⇒ 判定结果与无该阶段时逐字一致 | 同一输入跑「有/无阶段」两态，比对结果 | 硬判据 |
| 阈值改动无需重启 | 改配置后立即调用，断言行为已变 | 硬判据 |
| 新阶段失败 ⇒ 落到下一阶段且既有路径结果不变 | 注入故障传输层，断言 source 与结果 | 硬判据 |
| 响应缺字段 ⇒ 取保守值而非推测 | 构造缺字段响应，断言输出 | 硬判据 |
| 日志无原文 | 对日志做原文子串扫描，断言 0 命中 | 硬判据 |
| 日志含阶段来源标记 | 断言 source 字段存在且取值合法 | 硬判据 |
| 既有调用点零改动即可工作 | 旧签名调用编译并行为不变 | 硬判据 |

> 全部为**静态或注入式断言**，不依赖真实网络与真实模型。

## 5. 复查机制

- **复查周期**：每季度首周复查会（owner＝产品 owner），随《触发条件复查记录》一并过；
- **触发式复查**：新增任一外部模型阶段时，**必须**在同一个 PR 内逐条对照 §2 给出「满足/不满足/不适用」三选一，不满足者不得合入；
- **口径纪律**：本文件用逐条编号 `M-1`–`M-7`，**不引用任何上游编号体系**。
