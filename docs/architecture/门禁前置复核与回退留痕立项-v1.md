## 2. A 面：前置清单证据漂移自动复核（候选，零迁移可实施）

**触发场景**：清单项拍板 accepted 引用 evidence E1（hash=h1）；其后同一 `source_uri` 被重新采集/重交产生 E2（hash=h2≠h1，新行并存——T-G1 幂等语义）→ 清单项仍指向 E1，**平台现状无从提示「证据已换版」**。这恰是「前置复核」缺口：核验人看到的是已拍板绿标，无法感知其依据已被超越。

**设计（T-G2 同构，呈现层零迁移）**：
- `_serialize_gate` 清单项序列化时只读检测：同 `project_id + kind="gate"` 下存在 `source_uri` 相同、`id != evidence_id`、`content_sha256 != 该项哈希` 的**更新**证据行 ⇒ 项级输出 `evidence_superseded: true`（不携带新行指针——跳转走既有 evidence 登记簿面，`referenced_by=gate:Gx` 反查已有）。
- **呈现即提示，四不动**：门禁状态机不动、`claim_status` 不动、拍板有效性不动、AI 权限不动（呈现面 can_view 只读）。核验人据此自行决定是否重验（重验=既有重交通道，failed 可重交；passed/conditional 是否重验与回退相关联 → §3-B 面）。
- 有界性：仅比较**同 source_uri** 行集（每清单项候选集天然有界 ≤ 上限 20×清单项数）；不做全项目扫描。
- 判据（未来接线）：J＝拍板 accepted 的清单项，其 evidence 被同 uri 新 hash 行超越后，序列化必含 `evidence_superseded: true` 且状态机五值不变（变异：摘检测→红）。

## 3. B 面：拍板回退通道与留痕合同（候选＋拍板闸）

**现状缺口**：`passed/conditional_pass` 为终态（重交 409）——拍板后发现依据错误（如 §2-A 的漂移恰发生在拍板后）**无合法通道撤销**，只能靠 G8 `pivot/stop` 决策或项目级处理；`failed` 有重交回环。是否开放终态回退＝**业务拍板项**（回退本质是允许推翻一次人的核验，须谨慎），本文只登记选项与合同，**不预支裁决**。

**选项登记**：
- **B-opt1 维持现状**（回退不开放；错误拍板经 G8 pivot/stop 或线下流程修正）——零成本，登记即可销号。
- **B-opt2 受限回退**：NEW `decide_gate_rollback`（can_manage＋密码确认＋**验收分离沿用**：回退人≠原拍板人可选；仅 `conditional_pass`（条件未竟）可回退到 `evidence` 态、`passed` 不回退——上线语义最重，回退它=推翻交付事实）；留痕合同＝`OperationEvent` `gate_rolled_back`（from_status/to_status/reason 必填/actor/回退时点的 revision）；触发 §2-A 联动（`evidence_superseded` 呈现时 UI 提示可走回退，但**平台不自动回退**——责任主体永远是人）。
- **B-opt3 只读复核队列**：不回退状态，仅新增「待复核」标记队列（A 面的强呈现），核验人重走提交-拍板全流程产生新拍板——状态机零改动，流程最重。

**留痕合同（若采 opt2）**：回退事件必带 reason（文本≥1，落 `OperationEvent.changes`）；回退后清单项 `claim_status` 全量回 `claimed`（重验语义一致）；CAS 与验收分离闸原样生效；**同事务**翻转+留痕（gate_service 既有单事务纪律）。

## 4. 不做清单

- **不动 evidence 不可变性**（A 面纯读时呈现；B 面不改证据行）。
- **不做定时自动重核**（无采集通道可自动重哈希客户侧原件——指针目标在平台外；「自动」仅指呈现层自动检测，核验永远是人）。
- **AI 不代拍板/不代回退**（门禁铁三角红线维持）。
- **不动验收分离/P0-5/admin 闸/CAS**（既有四闸原样复用）。
- 不改 T-G1/T-W7 候选机制（换指纹并存语义保留——A 面恰恰依赖它）。
