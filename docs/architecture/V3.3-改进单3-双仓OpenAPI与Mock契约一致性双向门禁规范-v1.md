## 1. 源码级现状风险取证（Why）

双仓解耦（`fde-workbench` ⇄ `Fde-Ontology`）当前最大的一颗隐形炸弹，是 **`fde-workbench` 在单测与默认离线态（`FDE_ONTOLOGY_ENABLED=false` 或测试注入）依赖一份长达 793 行的手写 `MockOntologyAdapter`（`ontology_mock.py`）**。穿透比对两边源码，已经能直接抓到真实漂移苗头：

1. **指纹与 ETag 算法已经不一致**：
   - `ontology_mock.py:139`：`digest = hashlib.sha256(repr(snapshot).encode("utf-8")).hexdigest()[:16]`（用 Python `repr()` 字符串且截断 16 位）。
   - `ontology-service/fingerprints.py`：使用 `json.dumps(..., sort_keys=True, separators=(",", ":"), ensure_ascii=False)` 规范化 JSON 计算完整 64 位 SHA-256。一旦上层业务对 `snapshot_sha256` 长度或跨进程稳定性做断言，Mock 绿而真机必炸。
2. **状态机与错误码双头演进风险**：
   - ChangeSet 生命周期（`draft -> reviewing -> approved -> published` + 单活跃锁 `409 change_set_locked` + ETag 乐观锁 `412 Precondition Failed`）、Action 异人审批（`proposer_id != approver_id` → `403`）、幂等冲突（同 `X-Idempotency-Key` 异 Body → `409 idempotency_payload_mismatch`）在 FastAPI 真机与 `ontology_mock.py` 中各写了一遍，没有任何自动对账机制。
3. **跨仓契约文档无双向漂移闸**：
   - `fde-workbench` 已有极其成功的先例——`test_blueprint_registry_sync.py` 与 `test_api_safety` 双桥 45 样本等价性静态钉（CR-071）；但双仓之间尚未给 `ontology-api-spec.yaml`、`ontology-service` 真路由与 `ontology_mock.py` 上同一把锁。

## 2. 核心设计：三向黄金契约门禁（Tri-Way Contract Parity Gate）

不引入重量级 Pact Broker 服务器，直接复用本仓成熟的 **「共享黄金向量集（Golden Vectors）+ 差分状态机重放（Differential State-Machine Replay）」** 模式，建立三向锁死闭环：

```
          [单一权威契约包: contracts/ontology-v1/]
          ├── ontology-api-spec.yaml (OpenAPI 3.1)
          ├── spec-sha256.lock       (跨仓版本锁)
          ├── hmac-test-vectors.json (签名/Nonce/防篡改向量)
          └── golden-traces/*.json   (多步状态机差分用例)
                     │
       ┌─────────────┴─────────────┐
       ▼                           ▼
[Fde-Ontology CI]           [fde-workbench CI]
FastAPI TestClient (PG16)   MockOntologyAdapter + OntologyClient
1. 路由 ≡ OpenAPI Spec      1. spec-sha256.lock 防私改校验
2. 跑通全部 golden-traces    2. 跑通完全相同的一套 golden-traces
3. 导出归一化响应特征快照     3. 响应状态码/错误码/键集/ETag 语义 ≡ 真机快照
```

## 3. 具体技术改造规格（What to Build）

### 3.1 契约真身同步锁（消除无声分叉）

1. **权威源唯一化**：`Fde-Ontology/docs/v3.3/m1/ontology-api-spec.yaml` 为唯一主本；在 `fde-workbench` 新增 `contracts/ontology/ontology-api-spec.yaml`（只读镜像副本）与 `contracts/ontology/VERSION.json`：
   ```json
   {
     "spec_version": "1.2.0-m4",
     "source_repo": "caishide/Fde-Ontology",
     "source_commit": "89992b9",
     "spec_sha256": "<64位精确sha256>",
     "vectors_sha256": "<64位精确sha256>"
   }
   ```
2. **同步脚本**：提供 `scripts/contracts/sync_ontology_contract.py`，一键从相邻 `Fde-Ontology` 仓拉取最新 `ontology-api-spec.yaml` 与 `golden-traces/` 并重算 `VERSION.json` 指纹；CI 静态钉校验本地副本 SHA-256 必与 `VERSION.json` 一致，禁止在 `fde-workbench` 手改契约副本。

### 3.2 黄金向量集 1：HMAC 上下文与幂等协议向量（`hmac-test-vectors.json`）

参照 `CR-071` 双桥 45 样本等价性钉，沉淀 **20 条固定加密与协议测试向量**，两仓测试各自加载同一份 JSON 断言逐字节一致：
- 正向标准向量（含中文/特殊字符 `actor_id`、`org_id: null` 平台态 vs 企业 `org_id`、固定 `ts` 与 `nonce` → 断言生成的 `X-FDE-Context` Base64URL 串与 HMAC 签名逐字符相等）；
- 反向拦截向量（过期 `ts - 301s`、未来偏移 `ts + 301s`、篡改 `project_id` 1 字节、重放相同 `nonce`、缺少 `X-Idempotency-Key` 的写请求、同幂等键不同请求体 → 断言双方返回完全相同的 HTTP 状态码与 `error.code`）。

### 3.3 黄金向量集 2：状态机差分重放套件（`golden-traces/`）

定义与传输层无关的声明式测试剧本格式，通过薄驱动适配器分别在 `Fde-Ontology`（挂真实 FastAPI `TestClient`）和 `fde-workbench`（挂 `MockOntologyAdapter`）执行，比较归一化响应契约（`status_code`、顶层信封结构、`error.code`、关键投影键集合、ETag 变化律、SHA-256 格式正则 `^[0-9a-f]{64}$`）：

必覆盖的 **8 条核心黄金链路**：
1. **`trace-01-changeset-happy-path`**：创建 ChangeSet → 写入 ObjectType/Property → 校验 ETag 演进 → 提交审批 → 异人批准 → 发布生成不可变 `OntologyVersion`（断言 `snapshot_sha256` 为 64 位规范哈希）。
2. **`trace-02-single-lock-conflict`**：同一 `ontology_id` 已存在锁定窗口 ChangeSet 时再锁第二个 → 双侧均必返 `409` 且 `error.code == "change_set_locked"`。
3. **`trace-03-etag-optimistic-lock`**：携带过期 `If-Match` 修改 working-set → 双侧均必返 `412`。
4. **`trace-04-logic-eval-and-error`**：合法表达式求值 `200` vs 语法越界表达式 `422` 错误码对齐。
5. **`trace-05-action-two-person-rule`**：创建高风险 `ActionRequest`（`dry_run` → `propose`）→ **同一 `actor_id` 尝试 `approve` 必返 `403`** → 换第二 `actor_id` 批准 → `execute` 成功。
6. **`trace-06-idempotency-replay-and-mismatch`**：同一 `X-Idempotency-Key` 同参数重放返原结果（`replayed: true`）；同键改参数重放必返 `409`。
7. **`trace-07-cross-org-isolation`**：`org-A` 创建的本体与动作，`org-B` 上下文读取/操作必返 `404`（不泄露存在性，对齐 M3a §3.5 纪律）。
8. **`trace-08-d26-context-injection-block`**：在 MCP/Query/Action 请求体中混入 `actor_id` / `org_id` / `permissions` → 双侧均必返 `400`。

### 3.4 修复现有已知漂移点

在落地本改进单时，同步修平已发现的 `ontology_mock.py` 漂移：
- 将 `ontology_mock.py:139` 的 `repr(snapshot)` 替换为与 `ontology-service/fingerprints.py` 同款的 `canonical_json_sha256(snapshot)`，统一输出完整 64 位 SHA-256 指纹与标准强/弱 ETag 格式。
- 在 `Fde-Ontology` 新增 `tests/test_openapi_route_sync.py`：双向断言 FastAPI `app.routes` 注册的所有 `/v1/*` 路径+HTTP 方法 ≡ `ontology-api-spec.yaml` 的 `paths` 定义（复刻 `fde-workbench` 的 `test_blueprint_registry_sync.py` 成功经验，新增路由忘写 OpenAPI 即红灯）。
