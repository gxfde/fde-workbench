# 技能结构化契约 v1（B#36，PROPOSED——文档+测试，零迁移零运行时）

> 登记来源：`docs/implementation/v3-backlog.md` 开源借鉴清单 B#36/B#37（2026-11-06 登记）。
> 硬判据逐条声明：本契约为**我方独立设计**——法务结论（Q18）前不引用 fde-skills 任何正文，
> 不逐字搬其类目名/规则文本；只取「最小自描述契约」的**语义**，不取 21 字段全必填、
> 不设 `additionalProperties:false`。机器闸=同轮 B#37 `server/tests/test_skill_contract.py`。

## 1. 落点与权威

- **载体**：`SkillVersion.manifest_json`（JSON 列，既有）的**可选扩展组键**——免迁移；
  写路径不强制（保存/发布四闸零改动），消费方=治理评审人 + 静态测试。
- **权威边界**：`instructions_text` 的唯一权威永远是 DB 版本行——**禁止把指令拆成
  YAML 双权威**；本契约只约束自描述元数据，不碰指令正文。
- **值域纪律**：不换状态值、不新增 `draft·ready·field-validated` 类状态——验证状态组
  （§2.4）只做**非状态注记**，与 T-S1 治理态正交。

## 2. 五组语义（全部可选；值类型 str / bool / list[str]）

每组一个 `manifest_json` 顶层组键，组内 ≤2 键。语义锚全部指向我方既有平台语义
（对齐验收合同五点「字段语义同源」的登记要求——B#29/B#22 语义风格见
`docs/architecture/交付效果评测协议-v0.md` §4，但落点=技能契约，非 G8/G9 验收合同）：

### 2.1 `use_boundaries` 适用边界组

| 键 | 类型 | 语义 |
|---|---|---|
| `when_to_use` | str | 触发条件：什么意图/请求下应选用本技能 |
| `when_not_to_use` | str | 排除条件：什么情形下明确**不该**用（含应改用谁） |

锚：评测协议 §4 第 3 点「写明条件是什么、缺什么」（有条件通过不得粉饰边界）；
既有实践=file-delivery 种子「先确认用户明确要求发送文件；仅查询或查看不发送」。

### 2.2 `effects` 副作用声明组

| 键 | 类型 | 语义 |
|---|---|---|
| `write_actions` | bool | 是否含写类动作（改数据/改配置） |
| `external_side_effects` | list[str] | 外副作用面清单（发信/付款/外呼等，枚举语义=P3 评估报告 G6/G7 类目） |

锚：T-R2 `api_catalog` effect/risk 分面 + P3 评估报告「写外呼/发信/付款永不降级」红线
（`docs/implementation/v3-p3-评估报告-有限自动执行-v1.md`）。
**自洽律**：与既有简式基线键 `read_only` 并存时必须满足
`read_only == not effects.write_actions`（两套口径打架即契约违例——B#37 钉）。

### 2.3 `evidence` 证据口径组

| 键 | 类型 | 语义 |
|---|---|---|
| `artifacts_as_pointers` | bool | 产物是否以 source_uri+sha256 指针呈现（原件永不入库） |
| `evidence_gates` | list[str] | 产物可挂接的门禁编号（⊆ G1–G9） |

锚：证据红线（门禁证据只存指针+指纹）；挂接语义=T-G1/T-W7 候选挂接
（`gate_service.attach_task_evidence_candidate` / `attach_workflow_evidence_candidate`）。

### 2.4 `verification` 验证状态组（非状态注记）

| 键 | 类型 | 语义 |
|---|---|---|
| `verified_scenarios` | list[str] | 治理评审时实际验证过的场景清单（自由文本） |
| `unverified_note` | str | 未覆盖面的诚实说明（没验证过什么） |

锚：B#35「published＝治理通过 ≠ 现场验证」+ T-S1 发布四闸的 test_report/waive 语义
（有条件放行必须写明缺什么——不粉饰）。

### 2.5 `failure_behavior` 失败诚实组

| 键 | 类型 | 语义 |
|---|---|---|
| `failure_reporting` | str | 失败时的报告口径：区分未完成项与原因，不虚报完成 |
| `degrade_policy` | str | 降级行为声明：何时降级、降级后如何如实报告 |

锚：B#2 回执「写错不重做」终态语义（`succeeded_but_receipt_invalid`）+ P3 降级分类学 +
LCSC 种子「确实无法继续时分别说明未完成项及原因」既有实践。

## 3. 基线键与键空间

既有种子基线键（非契约组，维持不动）：`version` / `source` / `read_only`。

**契约键空间**（闭合枚举，防漂移——B#37 对我方自带种子/DB 行校验键 ⊆ 此空间；
对用户自建 Skill **不拒绝未知键**，只校验已知键的良构性）：

```
{version, source, read_only} ∪ {use_boundaries, effects, evidence, verification, failure_behavior}
```

## 4. `.agents/skills/` 新技能 front matter 建议（非权威）

仓库 runbook（`SKILL.md`）维持最小头：**必填 `name`+`description`**（name=目录名、
`fde-` 前缀）；五组契约键**可选平铺点路径**（`组键.子键: 值`；bool 用 `true/false`、
list 用 JSON 数组字面量、str 用非空文本），与 manifest_json 嵌套形态一一映射。
front matter 只是仓库侧建议头——**入库后以 DB 版本行为准**（§1 权威边界）。
存量 4 个 runbook（fde-bridge-capture / fde-delivery-flow / fde-gui-regression /
fde-package-verify）**不回填**。

## 5. 非目标

- 不改发布四闸、不换状态值、不加写路径强制校验（契约键纯可选）；
- 不引入 PyYAML/jsonschema（B#37 用标准库+pytest）；
- 不做技能组合自动执行化、不做批量导入（B#40 不做清单上位维持）；
- 存量内置种子 manifest 维持三基线键——本契约不回填任何既有行。
