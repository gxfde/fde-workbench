## 0. 一句话拆解

访谈录音→文字这条链在平台代码中**不存在**（上位方案缺口表 G3），且现役 AI 供应商均无音频转写能力 ⇒ ASR 通道须独立选型。本文只做三件事：**逐字钉死红线**（录音与未确认转写的入库边界）、**行级实测现状**（证明现成通道做不了）、**把通道选型作为显式拍板项清单交蔡工**（不代决）。T-A9 的草稿区承接机制（表/清理/晋升）在 backlog 登记原文中已齐备，本文只引用不重述实施。

## 1. 红线锚点（逐字引用，永不改写）

SOP 原文 `D:/test/FDE/engagements/openfde/engagements/somwyn/raw/2026-10-27-FDE接触调研阶段资料入库SOP设计.md`（本仓外，指针+指纹纪律同证据红线——原件只留项目工作目录）：

- **`:109`**：「**AI 在接触阶段能做的三件事**（恰好对应 somwyn 已验证的三段能力）：问卷读卷分级（AI 打分 + 理由）、触达文案生成（对应 `01-website-grounded-cold-email` 工作流）、初诊录音转写（⚠️ **只转写不入正式库**，且必须先获口头同意）。」
- **`:111`**：「**S2 红线的特别提醒**：S2 明令「不录音转写入库」。新增 `leads/raw/` 存企业填写的问卷原文后，极易被误解成「可以存原始材料」。**边界是：企业主动发给你的文字可以存；你录的音不能存。** 这条线要守死，否则 S2 免费初诊就变成带录音的免费咨询。」

上位方案 v1.2 §10 Q2（2026-11-06 复审改判，`售前驱动交付模式改造方案.md:399-418`）据此**改判**：**音频文件仅在本地临时留存并转写；转写结果只入草稿区（不可引用、T+7 自动清理），售前人工整理为访谈纪要并经客户确认后才入正式库**。v1.1 原「转写文字可入库」结论作废。两条 SOP 锚的强弱关系已在上位方案钉明：`:109` 的「只转写不入正式库」比 `:111` 的边界句**更严**——连转写文字都不入正式库，不是「只禁音频」。

**本立项的三条硬边界（从红线直接派生，任何通道形态都不得豁免）**：

1. **录音原件永不进 repo/DB/远端**——只在项目工作目录本地临时留存，转写完成后按 T-A9 清理语义处置；
2. **未确认转写文本只落草稿区**（不可被方案/报价/SOW 引用，T+7 自动清理）；
3. **转写文本过 T-A2 代号化管线**（企业名→代号），**不因「草稿」豁免**。

## 3. 通道选型（候选与红线张力——**交蔡工拍板，不代决**）

### 3.1 候选清单

| 候选 | 形态 | 客户语音去向 | 与红线的相容性 | 主要成本/风险 |
|---|---|---|---|---|
| **opt-L 本地 ASR** | whisper.cpp / faster-whisper / FunASR（Paraformer）等开源模型，跑在 Windows 宿主工作机（与 `bridge-poll.mjs`「采集只能在 Windows 宿主跑」同款宿主形态） | **不出工作机** | ✅ **红线同向**：录音与转写全程本地，零新增外发通道 | 中文准确率与长录音耗时须真机实测；模型文件数百 MB–数 GB 须人工预置（不入仓）；宿主算力占用 |
| **opt-C 云 ASR** | 境内云厂商语音转写 API（阿里/腾讯/讯飞等），或托管推理端点 | **客户语音外发至第三方** | ⚠️ **红线张力显式登记**：触碰「客户真实资料永不外发」与「不新增外发通道」两条——录音是比文字更敏感的生物特征载荷，且客户口头同意的范围未必覆盖「送第三方云」 | 每分钟计费；供应商留存策略须逐家核；**若采此路＝显式红线例外，须蔡工逐项拍板（供应商/留存/同意话术扩展），平台不默认开启** |
| opt-H 混合（本地为主，云兜底） | opt-L 常规；长录音/低置信时提示人工改走云通道 | 按触发路径分流 | 张力同 opt-C，但收敛为「显式人工选择、逐次确认」 | 两套链路维护成本；触发判据是新规则面 |

### 3.2 张力分析与推荐

- **张力核心**：录音转写链的输入是客户语音。SOP :111 允许的边界只覆盖「企业主动发给你的文字」——语音本就不在该边界内（`:109` 特批的是「只转写不入正式库」这个动作，且「必须先获口头同意」）。**本地 ASR 把同意范围维持在「录音并转写、不外发」的字面内；云 ASR 把「第三方云处理」塞进同意范围，需要新的明示同意**。
- **推荐＝opt-L 本地 ASR 先行**：红线同向（零外发）、零按分钟计费、与宿主采集形态同构；先真机实测中文准确率与耗时（访谈场景单段 ≤1–2 小时量级），实测报告作为 T-A9 实施轮的前置输入。**若实测质量不达标再议 opt-C/opt-H——届时作为显式红线例外重新拍板，本文不预支**。

## 4. 承接机制（引用 T-A9 登记原文，不在本文重复设计）

T-A9 实施轮的承接机制以 backlog 登记原文为唯一权威，此处仅引用要点防断链：

- **草稿区**＝独立表 + **独立文件根物理隔离**；**T+7 自动清理**；
- 草稿行**不可被方案/报价/SOW 引用**（验收：无客户确认的转写文本无法进入正式库）；
- **晋升**须带客户确认人/时间戳/确认方式三要素；
- **转写文本过 T-A2 代号化管线，不因草稿豁免**（§2 锚 5 已有管线可直挂）；
- 草稿写入/读取 API **不进 api_catalog**（沿真相层与业务对象纪律）；
- 且实施前提：**须先获客户口头同意方可录音**（SOP :109 逐字）。

## 5. 不做清单（本立项的边界）

- **不做 T-A9 本体实施**：草稿区表/文件根/API/桌面录入入口/清理作业/晋升流——全部留 T-A9 实施轮（选型拍板后另开）。
- **不做 ASR SDK/模型接入**：不装依赖、不下模型、不改 `ai/` 任何模块；`kimi.py` 的 purpose 枚举注释仅为现状实测引用，不做「顺手扩枚举」。
- **不做录音存储**：录音原件永不进 repo/DB/对象存储/远端——连「临时库」都不建，临时留存语义属 T-A9 实施轮的草稿区设计。
- **不新增外发通道**：云 ASR 属红线例外面，默认不开（§3.3 P6）；任何实施轮不得以「ASR 需要」为由新增外发面。
- **不动 T-A2 管线**：代号化三道防线与 #171 复核闸原样复用，不为草稿区开豁免口。
