> 来源：`docs/implementation/v3-backlog.md` P1 第二批 B#13（原文仅登记「统一到期表+审批主动超时」，未展开）。

## 1. 问题与目标

当前有多种时钟字段都被泛称「到期」，但领域含义不同：审批截止、一次性确认窗口、上传临时资源 TTL、
派单响应期限、worker lease、重试可用时刻、令牌/签名 TTL。统一它们的**审计/查询语义**有价值；
统一成一张重复存储所有时间戳的业务表会制造双权威、竞态与错误副作用。

**目标**：

1. 用一份可审计目录描述各业务域原生的到期时刻、权威字段、到期后转换、清理动作、重复执行语义；
2. 让各域按自己的状态机主动收敛过期对象，不依赖用户再次触碰；
3. 后续需要跨域查询时提供**只读投影/统一视图**，不迁移或复制领域截止时刻，不取代各域原生状态机；
4. 维持既有主动审批超时为基线能力，并通过合同与专项测试钉住。

## 2. 核心裁决：统一目录+只读投影，不建通用到期事实表

**不新增**泛化 `expirations`/`deadlines` 表来复制 `expires_at`，不将业务状态转换外包给通用 worker。

统一到期记录的逻辑视图（若后续产品确有查询需求，首选 SQL view 或服务层只读 union）：

| 逻辑字段 | 语义 |
|---|---|
| `domain` | 稳定域名，如 `automation_approval` / `upload_session` / `api_confirmation` / `dispatch_offer` |
| `object_id` | 源领域稳定 ID；只作为反查键，不单独持久化 |
| `deadline_at` | 从源行/事件/明确 TTL 规则即时读取的截止时刻；不得复制为第二事实 |
| `state` | 源领域当前状态；投影只读，不写回 |
| `due` | `state` 仍处于该域可到期集合且 `deadline_at <= now` |
| `expiry_action` | 指向领域转换器/服务原语的符号名，不执行任意字符串命令 |

该视图不是用户功能前置条件；**先交付语义目录与各域正确收敛，再由产品需求触发 UI/API 列表**。零必要性不建空壳。

## 3. 统一语义合同

每个纳入域须有一条登记，最少回答：

1. **权威时钟**：截止值存于哪张原生表/事件，或由哪条已版本化常量推导；不得有两个可编辑权威；
2. **适用状态**：哪些状态仍可到期、哪些是终态/并发成功态；
3. **截止边界**：统一使用 UTC；严格定义边界（`deadline_at <= now` 到期，等于边界也到期）；
4. **转换原语**：唯一执行状态转换与 domain side effect 的服务函数；惰性查询、人工操作和后台 sweep 必须复用它；
5. **并发与幂等**：有限批次、稳定排序、行锁 `skip_locked`；重复 sweep 无重复事件/清理/通知；迟到消费者不得覆写已终态对象；
6. **副作用**：关联 run/node/package/object storage/outbox 的同步变更逐项声明；存储 API 失败时的重试/留痕/补偿策略必须明确；
7. **时效**：后台巡检周期及最大可接受迟滞；用户操作路径仍须防止越过 deadline 的迟到成功；
8. **可观测**：按域统计 due/transitioned/failed-cleanup 数量；日志不含客户真实资料、凭据、对象正文或未脱敏载荷。

后台 sweep 的失败必须可重试/可见，不能把「扫描到」报告成「已收敛」。

## 4. 域目录与当前状态（2026-11-06 实测 fork/main=`7b4b071`）

| 域 | 权威时钟/当前语义 | 现状/阶段裁决 |
|---|---|---|
| **automation approval**（含 workflow human_approval） | `automation_approvals.expires_at`；pending→expired；唯一转换原语 `control.service._expire_approval`；审批超时使 automation run failed(`approval_expired`)，workflow node 走 T-W4 断链失败并重投 | **已实现（T-P1-5）**：惰性 decide/status + `scheduler.sweep_expired_approvals(skip_locked)`，与 scheduler 同拍；本立项只补目录/回归合同，不重复造表/重做 sweep |
| API 高风险确认 | `ai.api.requested` 的 `OperationEvent.created_at + 15m`；事件日志 append-only；target fingerprint/auth_version/「started but uncertain 绝不重放」保护 | **待评估阶段**：目前 pending/status/decision 三处推导；如需主动超时，先设计不改写事件事实的只读视图或 append-only expiry event；不可移入 AutomationApproval，不能自动执行/重放 |
| multipart 上传会话 | `upload_sessions.expires_at`；sign/complete/abort 由服务端行锁复核 `expires_at <= now`；对象存储 multipart 清理由 worker 负责 | **已实施（B#13-B，零迁移）**：迟到 sign/complete 409 零 storage/文件副作用，签名 TTL 不越会话截止；scheduler `skip_locked` claim→`file.upload.cleanup` outbox→worker 事务外 abort；not-found 幂等成功，其他错误稳定账本+recoverable/backoff；专项 8 例、邻域共 65 passed |
| dispatch offer | `offer_deadline(mode, package)` 派生（claim 15m / assign response window）；现有 daily maintenance 执行 `offered→expired`、响应戳/version/event/package 收敛 | **既有域**：补入目录，不复制 deadline，不替换派单专属原语 |
| Channel binding / Weixin QR login | 各自原生 `binding_expires_at` / `login_expires_at`，一次性校验/惰性展示 | **仅目录**：未证明需后台物化状态；不为清理 UI 残留增加写路径 |
| worker lease / retry / outbox due time | `locked_until` / `available_at`（lease、重试调度、投递时刻） | **排除**：非业务到期；租约过期可能重新执行幂等 handler，语义不同 |
| access/refresh/MCP/JWT、signed URL、Redis TTL、模型/进程超时 | token claim/签名/缓存/运行时截止 | **排除**：安全或传输层时效，已有组件验证，不建 DB 到期队列 |
| dispute SLA / meeting stale / plugin approval / planned dates | SLA/惰性清扫/产品排期等 | **本期不纳入**：状态转换责任和 SLA 承诺未统一立项；不得按字段名 `expires` 自动纳入 |

### B#13-B：UploadSession 主动到期（**DONE，2026-11-06，代码轮**）

实现复用既有 `UploadSession.status=expired` 与 `expires_at`，**零迁移**：`service.py` 的 sign/complete/abort 路径行锁复核 `expires_at <= now`；迟到 sign/complete 不触碰 storage、不建文件版本，返回 `upload_session_expired` 409；分片签名 TTL 收窄为不超过会话剩余时间；complete 与 expire 单行锁单赢家，已完成 replay 语义不动。

新增 `files/expiration.py`：scheduler 以 `skip_locked` 批量将 uploading→expired，在同事务写 `completion_json.expiry_cleanup` 账本并投递 `file.upload.cleanup` outbox；worker 在 DB 事务外调用 multipart abort，再独立事务标记 succeeded；`multipart_upload_not_found` 视为已清理成功，其他 storage 错误保留稳定错误码并沿 BackgroundJob recoverable/backoff 重试；scheduler 不执行远端存储调用。handler 注册、reconcile 可恢复集合与 scheduler 同拍接线均已完成；无人工 actor 事件、无新外发通道。

测试 `test_file_upload_expiration.py` 8 例 + 既有 upload/worker/reconcile 回归，合计 **65 passed**：边界 `expires_at == now`/迟到无副作用/签名 TTL 收窄/重复 claim 单 outbox/cleanup 成功与 not-found/失败账本+worker 终态/recoverable+active job dedup；mypy 官方闸 279/104，ruff 全绿。B#13-B 完成；B#13-C API confirmation 与 B#13-D 跨域只读投影仍 PROPOSED。

### B#13-C：API confirmation 主动超时（候选文档/代码阶段，独立授权）

## 6. 总体非目标与红线

- 不建重复 deadline 表、不迁移既有到期字段、不把所有 `expires_at`/timeout/TTL/lease 统一进业务队列；
- 不改变审批密码确认、权限复核、风险等级、审批/工作流状态机；审批到期不得自动批准；
- 不自动执行写类 external，不发送微信/邮件提醒，不创建第二外发通道；
- 不清理/读取客户资料原件，不将其放入 git/数据库；门禁证据仍只存 source_uri+sha256，原件留工作目录；
- 不把 worker 重试/lease、令牌/签名/Redis TTL、模型网络 timeout 与业务审批 deadline 混为一类；
- 新增代码不得要求新依赖；所有时间统一 UTC，测试通过注入 `now` 固定边界。
