## 1. 目标与完成定义

### 1.1 终点判定（AI 原生的可操作定义）

**终点 = 抽离测试通过**：把系统里的 AI 模块整体拿掉，交付主干必须崩塌（即主干依赖 AI 的产出而非 AI 只是内容处理器）。
判据（三条同时成立，缺一不可）：

1. **决策位有 AI 行使**：方案/用例/DAG/派单推荐中至少三条链路的产出来自 AI 起草 → 人工审核 → 发布；
2. **飞轮有回流闭环**：人工接受信号被 AI 面消费、审计可按提示词版本归因、评测进 CI、改进提案有受控发布通道；
3. **执行面有真实订单**：至少一个含 agent run 的**真实客户订单**走通到 G9（不是演练、不是模拟场）。

### 1.2 四特征目标分与翻分判据（引用评估 §4 的 0–3 标尺）

| 特征 | 起点（现测） | 本期目标 | 翻分判据（复测口径） |
|---|---|---|---|
| ①智能内生 | **2/3** | **3/3** | G-02（受确认闸的 AI 发起）+ G-03（AI 起草 DAG）落地**且**执行面真实订单首跑 |
| ②数据飞轮 | **1/3** | **2/3**（3/3 属 L4 段） | 人工接受信号被消费（G-08）+ 审计按提示词版本归因（G-09/G-16）→ 首圈失败可归因到具体提示词版本 |
| ③人机协同 | **2/3** | **3/3** | 真实订单含 agent run 首跑 + G-15 桌面编排面落地 |
| ④持续进化 | **1/3** | **2/3**（3/3 属 L4 段） | 模拟场/评测跑出第一批真模型评估数据 + G-13 版本注册 + 受控发布通道（G-11） |

> **翻分只认复测证据**，不认措辞。判分复测随每轮回写台账（§5.1）。

### 1.3 本期明确不做

- **L5 全自主**、多 Agent 编排、门禁拍板 AI 化、客户沟通自动化；
- 对外口径变更（BP §1.3a 的对外表述以蔡工拍板为准，本书不改招商材料；评估/台账/本书均为**内部文档，不随招商外发**）；
- 提示词自动改写（只允许「生成复审工单」，不允许 AI 自改提示词后上线）；
- 任何以「消解差距」为由触发的**红线放宽**。

## 5. 台账操作规程（认领 → 施工 → 复测 → 回写）

### 5.1 四态与回写字段

| 状态 | 含义 | 何时置 |
|---|---|---|
| `OPEN` | 未实施 | 初始 |
| `IN_PROGRESS` | 在途 | leader 认领时（须同回合填轮次号与分支） |
| `CLOSED` | **消解判据复测通过** | 复测通过时（须附命令与原始输出） |
| `WONTFIX` | 有意不消解 | 须注记理由与替代路径 |

**每条 G 的回写四要素**：① 状态；② 实施轮 + PR 号；③ 复测命令与结果（可重放的命令，不写「已验证」）；④ 偏差注记（判据部分达成 / 行号漂移 / 语义漂移）。

### 5.2 复测规程（判据怎么算「消解」）

一条 G 从 `IN_PROGRESS` 到 `CLOSED`，须有**四证**（按适用性取舍，最少两证且必含「活库或测试」与「静态钉」）：

1. **静态证据**：grep/锚点确认结构在位（符号 + 行号，行号漂移按符号重 grep）；
2. **动态证据**：活库只读查询（真实数据，非构造样本）或 CI 实测；
3. **行为证据**：有**可辨变异**的用例（改坏 → 红 → 还原 → 绿）——尤其契约类；
4. **反向证据**：证明「AI 不代拍板 / 红线未放宽 / 写外呼未降级」的负向用例。

> 「结构在仓」≠「能力已验证」：G-12 同款纪律——CLOSE 的判据必须落到**行使**，不是落到文件存在。

### 5.3 锚点纪律

- **行号漂移不算失效**：按符号重 grep 即可（台账口径已声明）。
- **语义漂移必须复核**：锚点所指行为变了（条件、字段、值域、默认值），无论行号变没变都要在本行注记。
- 本轮基线下已知的漂移：`ai_call_audits` 表名行 `workbench/models.py:920`（类 `AICallAudit`）/ `:927`（`__tablename__`）；其余 §2.1 结构口径见台账 v1.2。

### 5.4 口径现测配方（leader 开工前必跑）

| 口径 | 配方 |
|---|---|

## 7. 红线（不可逾越，实施轮同样受约束）

1. **AI 不代拍板**：门禁拍板、审批、终审永远是人工（H1–H13 强制人工节点）。
2. **客户真实资料永不进 git 历史与远端**（仓库与库只存代号）。
3. **门禁证据只存 `source_uri` 指针 + sha256**；AI 产物原件永不入库。
4. **写外呼、发信、付款永不降级、永不自动**（`file_send_wechat` 事前密码确认边界维持）。
5. **密钥不入 VCS**；`origin`（上游 gxfde）**永不 push**，工作远端是 `fork`（caishide/fde-workbench）。
6. **AI 审查不执行被审代码**——审查输入只能是 diff/文本快照。
7. **宿主通道五边界**（红线第 5 条）不因「开通道」而放宽。
8. **「写错不重做」语义**（`succeeded_but_receipt_invalid`）与 L0–L3 降级链是自主化安全底座，Path 1–3 不得绕开。
