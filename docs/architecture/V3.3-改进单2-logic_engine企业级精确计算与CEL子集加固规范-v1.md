## 1. 源码级现状问题诊断（Why）

穿透审计 `ontology-service/src/ontology_service/logic_engine.py`（共 317 行），当前 M4 首版虽然完美守住了「零任意代码执行」红线，但在进入制造业质量追溯（§11）、客服抽检判定与商业计量阈值时存在 **4 个实打实的工程缺陷**：

1. **二进制浮点数精度事故隐患（P1 级计算缺陷）**：
   - 锚点：`logic_engine.py:44` 将 `"number"` 映射为 `(int, float)`，`_eval`（186–205 行）直接使用 Python 原生二进制浮点算术。
   - 现场后果：`0.1 + 0.2 == 0.3` 求值为 `False`；制造业不良率阈值判定 `defect_rate <= 0.03` 或财务税额/折扣核算在边界值上会发生静默误判！
2. **表达力仅限平面标量，无法承载真实 ERP/MES 批次聚合规则**：
   - 锚点：`_walk`（143–175 行）仅放行 `Eq/NotEq/Lt/LtE/Gt/GtE` 与单层 `input.<field>`，不支持 `in / not in` 枚举集合包含，不支持对批次检验记录列表做 `sum / avg / any_of / all_of / count` 归约，也不支持日期时间差值（如「来料批次距今超 180 天」或「检验时间早于投产时间」时序异常检测——恰是 M6-D2 要求注入的第 4 类脏数据场景！）。
3. **热路径重复 AST 解析开销**：
   - 锚点：`run_expression`（297–317 行）先调 `validate_expression` 跑一遍 `ast.parse` + `_walk`，紧接着第 312 行又调 `_parse(expression)` 再跑一遍 `ast.parse`，在高频批量规则评估（如 100 条双盲抽检）下平白浪费一倍解析 CPU。
4. **缺少空值安全（Null-safety / Three-valued fallback）**：
   - 真实企业脏表大量字段为 `NULL`（M6-D2 第 2 类脏数据：3% 检验记录缺失批次号/数值），当前 `SCHEMA_TYPES` 一刀切报 `LogicInputError` 抛异常中断整批，缺少显式 `nullable: true` Schema 声明与 `coalesce(input.val, 0)` 安全兜底函数。

## 2. 加固设计原则（对齐 Google CEL 核心哲学）

1. **铁律不退让**：继续 **100% 禁止图灵完备循环（无 `while`/`for` 语句、无递归、无 `eval`/`exec`/`getattr`、无属性双下划线穿透）**，任何合法表达式在编译期即可证明在有限步 $O(N \times K)$ 内必定终止。
2. **十进制精确数值默认化（Decimal-First Arithmetic）**：所有字面量浮点数（经源码词法/AST 提取字符串转换，而非经 `float` 中转失真！）与输入 JSON 数值统一提升为 `decimal.Decimal`（固定受控上下文：`prec=28, rounding=ROUND_HALF_UP`，捕获 `DivisionByZero` / `InvalidOperation` 转确定性 `LogicRuntimeError`）。
3. **受界集合归约宏（Bounded Collection Macros）**：借鉴 Google CEL 的 `exists` / `all` / `filter` 思想，但不开放任意 Python 推导式语法，而是提供 **强类型受界归约原语**，硬封顶单次输入列表最大长度 `MAX_COLLECTION_ITEMS = 1_000`、总求值步数预算 `MAX_EVAL_STEPS = 10_000`。

## 3. 具体技术规格（What to Build）

### 3.1 Schema 类型系统升级（向后兼容 v1）

在 `logic_engine.py` 扩展字段定义，支持简写字符串（100% 兼容现有 `"number"` / `"integer"` / `"string"` / `"boolean"`）与结构化对象声明：

```json
{
  "defect_rate": "decimal",
  "status": {"type": "string", "nullable": true},
  "produce_date": "date",
  "inspect_date": "datetime",
  "records": {
    "type": "array",
    "max_items": 500,
    "items": {
      "passed": "boolean",
      "score": "decimal",
      "defect_code": {"type": "string", "nullable": true}
    }
  }
}
```

- **`"number"` 与 `"decimal"` 统一走 `Decimal` 精确路径**：输入 JSON 中的 `int`/`float`/数字字符串均通过 `Decimal(str(val))` 无损转入；输出序列化时若 `output_schema` 为 `"number"`，提供精确量化后的 `float`（向后兼容旧契约）并在响应附带精确字符串表示或当声明为 `"decimal"` 时直接输出规范十进制串。

### 3.2 新增受控运算符与安全函数白名单（`_ALLOWED_FUNCS` v2）

| 类别 | 新增原语签名 | 业务用途（直击制造业与抽检试点） | 安全边界控制 |
| :--- | :--- | :--- | :--- |
| **成员判定** | `ast.In`, `ast.NotIn`（右操作数仅限字面量元组/列表或声明的枚举数组输入） | `input.severity in ("CRITICAL", "MAJOR")` | 右侧长度 ≤ `MAX_COLLECTION_ITEMS`，禁止子串隐式大文本扫描（字符串仅允许枚举列表成员匹配） |
| **空值安全** | `coalesce(a, b)`、`is_null(x)` | 处理 ERP/MES 3% 缺失列脏数据：`coalesce(input.yield_rate, Decimal("0"))` | 参数个数固定（`coalesce` 2–4 参，`is_null` 1 参） |
| **集合归约** | `count_items(arr)`、`sum_field(arr, "score")`、`avg_field(arr, "score")`、`min_field(arr, "score")`、`max_field(arr, "score")` | 客服 100 条双盲抽检均分、同批次多工序不良品累计数 | 第二个参数**必须是编译期静态字符串字面量**，且必须在 `items` Schema 中存在且类型为数值！杜绝动态字段注入 |
| **集合量词** | `any_match(arr, "passed", False)`、`all_match(arr, "passed", True)` | 「任一关键工序检验未通过即拦截放行」（对齐 CEL `exists` / `all`） | 字段名静态校验 + 求值步数计入 `EvalBudget` |
| **时序计算** | `days_between(d1, d2)`、`hours_between(dt1, dt2)`、`is_before(dt1, dt2)` | 检测「检验时间早于投产时间」时序倒挂脏数据、保质期剩余天数预警 | 仅接受 ISO-8601 标准日期/带时区时间戳（强制带时区或显式 UTC，对齐仓库 CI 无本地 TZ 依赖纪律） |
| **数值修约** | `round_half_up(x, digits)` | 财务金额保留 2 位小数、良率保留 4 位小数（替代 Python 默认银行家舍入 `round` 的惊讶行为） | `digits` 限制在 `[-6, 10]` 整数常量 |

### 3.3 编译缓存与步数熔断器（`CompiledRule` + `EvalBudget`）

重构 `logic_engine.py` 执行管线，消除双重解析：

1. **`compile_expression(expression, input_schema_json) -> CompiledRule`**：
   - 使用 `@functools.lru_cache(maxsize=512)` 缓存（键为 `(expression, canonical_schema_sha256)`）。
   - 编译期一步完成：词法级浮点字面量转 `Decimal("...")` AST 重写 + 节点数校验（`MAX_NODES = 250`）+ AST 深度校验（`MAX_AST_DEPTH = 24`）+ 字段存在性与静态类型推导（Type-checking at compile time！例如把 `"string"` 传给 `abs()` 在保存 ChangeSet 时直接报 `422 LogicValidationError`，不等运行时才炸）。
2. **`EvalBudget` 运行时步数守卫**：
   - 每次 `run_expression` 实例化 `budget = EvalBudget(max_steps=10_000)`，每访问一个 AST 节点或迭代一个数组元素 `budget.tick()`，超限立即抛 `LogicBudgetExceededError`（映射 HTTP `422`），彻底免疫构造大数组笛卡尔积导致的 CPU DoS。
