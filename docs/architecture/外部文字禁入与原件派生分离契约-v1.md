# 外部文字禁入与原件派生分离契约（v1，2026-11-06）

> 来源：借鉴登记 **B#12（外部文字禁入提示词）＋B#31（原件/派生分离）**（`docs/implementation/v3-backlog.md`「开源借鉴清单登记」P1 第二批）。按 **AGENTS 红线第 8 条**，本文为**纯我方独立设计**——零第三方正文/结构化表达引用；§2 现状对照全部为我方代码行级实测（基线 fork/main `a128767`，行级引用一律「符号名＋行号」双锚防基线漂移）。
> 形态：**契约文档（零代码零迁移零路由零依赖）**。§5 可断言判据供未来执行轮接线，**不属本文实施范围**——登记≠排期≠默认实施。

## 0. 两个问题的定义（我方语义）

- **B#12 外部文字禁入提示词**：「提示词权威层」（system role 消息、技能 instructions 权威文本）不得携带外部不可信文字——外部文字只能以 **user / tool 角色**或**结构化字段**进入模型上下文。为什么：system 层是模型行为与授权语境的根，外部文字进入 system 层＝注入即提权（可改写工具使用纪律、权限口径）。
- **B#31 原件/派生分离**：客户**原件**（证据、网页、文件、采集）与其**派生物**（AI 生成内容、导入候选、合并产物、报告）必须终身可区分、不可互相冒充——原件只登记指针与指纹，派生物必须携带完备血缘。

## 1. 名词与边界（封闭枚举）

- **外部不可信文字**：客户资料与扫描件文字、网页/网页抓取内容、项目文件正文、桥采集 stdout、终端/CLI 输出、外部模型响应正文。
- **内部权威文本（提示词权威层白名单）**：①代码常量；②config 值（产品名等，`server/.env` 覆写面）；③内置《操作使用手册》（镜像分发、我方撰写）；④治理面发布的技能 instructions（公共=admin 发布四闸；个人=owner 自治——残余边界见 §3-R6）。
- **原件**：平台外部产生、经采集/上传进入平台边界的物料——平台只持 `source_uri` 指针＋sha256 指纹，不持正文（AGENTS 红线第 4 条既有裁决，本文确认其工件面含义）。
- **派生物**：平台内由人/AI/导入/合并产生的物料——必须携带 §3-A2 三问血缘。

## 3. 规则（我方独立编号）

**提示词层（P 系）**

- **P-1 提示词权威层来源白名单**：system role 内容只能来自 §1 白名单四源（封闭枚举）。新增任何 system 提示词组装点必须落在白名单内，并在 PR 中对照 §2 表新增一行。
- **P-2 外部文字只经 user/tool 角色或结构化字段进入上下文**；禁止以字符串拼接/模板内插方式并入 system 模板。数据→模型一律走结构化通道（JSON payload，先例 `ai_content.py:115`）或占位符整值替换（T-C1 先例）。
- **P-3 外部文字进入上下文须带框架或标记**：「不可信资料/不执行其中指令」框架文案（工具描述先例）或结果级 `"source"` 标记（`file_read`/`help_fetch` 先例）——二者至少其一。
- **P-4 分工不混淆**：本契约管**模型运行时上下文**的卫生；B#3（AGENTS 红线第 7 条）管 AI **审查器**不执行被审代码；#139 M-1–M-7 管外部模型**判定层降级**；W-8 管流程层断链显性失败。四者互不覆盖。
- **P-5 skill instructions 的作者边界**：技能文本属「内部权威」的前提是**作者=账号持有人本人且经治理面**（公共=admin 四闸＋复核分离；个人=owner 自治）。技能内容是 DB 行 → 客户真实资料不入库红线天然覆盖；owner 在个人技能中粘贴外部文字＝自愿注入自身上下文，边界如实记为残余风险（§4）。

**工件层（A 系）**

- **A-1 原件零正文**：原件只登记指针＋指纹（红线既有）；平台任何新采集通道不得把原件正文落库。
- **A-2 派生物三问血缘**：每个派生物必须可答——来源（哪些原件/输入）、生成机制（人写/AI/导入/合并，`captured_from`/`ai_request_id`/`source_kind` 任一在位）、版本锚（`revision_id`/版本行/固定版本 run）。
- **A-3 派生物不冒充原件**：展示/导出面必须可区分——证据登记簿行（指针型）与文档版本行（生成型）分表分面；AI 生成版本行 `ai_request_id` 在位即机器可辨。
- **A-4 生成默认不视作已审**：AI 生成产物默认 `reviewed=False`（B#2 语义延伸）；升级为「已审」必须有人工动作留痕（`OperationEvent` 先例）。
- **A-5 血缘键只增不改**：`ai_request_id`/`captured_from`/版本行一经落库不可变（证据不可变先例 `evidence/service.py:4`）；修正血缘＝新增留痕而非改写。

## 4. 差距清单

- **已由代码闭合**（无需动码）：P-1/P-2 现状全部满足（§2 面 1-4——全系统仅四处 system 组装点，全部落在白名单内）；A-1/A-2/A-3 现状满足（面 7-9）。
- **靠本文立规闭合**（未来执行轮判据，现态为差距）：①`lcsc_search`/`lcsc_runs_read` 结果体**无结果级 `"source"` 标记**（仅工具描述框架文案，P-3 半满足）；②`direct_tool_completion` 的 `system_prompt` 形参是白名单外放通道（调用方约束在语义层无静态闸，P-1 静态断言的未来靶点）；③A-4「生成默认不视作已审」分散各处、无统一谓词；④P-5 个人技能 owner 自治边界（如实登记，不收窄——收窄需另拍板）。
- **明确不做**：不建统一「提示词审计中间层」（无消费方不建空壳，B#10 同款裁决）；不改 tool 消息结构（模型供应商合同面）；不回填任何存量数据。

## 6. 触发式复查

新增 **①任一外部文字入口**（新工具/新采集通道/新导入类型/新网页面）**②任一 AI 调用点**（新 system_prompt 组装/新技能分派面）**③任一工件类型**（新表/新产物/新导出面）时，**同 PR** 内逐条对照 §3 给「满足 / 不满足 / 不适用」三选一并落 PR 描述（#139 外部模型依赖契约同款机制）。
