## 1. 四层状态归属总表

| 层 | 真相持有方 | 引用/派生方 | 归属不变量 | 违反后果 |
|---|---|---|---|---|
| project_evidence | `project_evidence` 行 = (project, source_uri, content_sha256) 指纹三元组，**不可变、同指纹幂等** | 门禁清单项（只持 `evidence_id`）、评测 result（同 schema 复用） | 引用方永不复制真相，只持指针；证据原件永不入库（红线：只存 source_uri + sha256） | 两处漂移 → 引用失真，对账失败 |
| ontology_* | confirmed 术语/关系类型行（`ontology_terms` 等） | 变更集 `ontology_change_sets.proposed_json`（候选）+ `base_snapshot_sha256`（提交时基线指纹） | **confirm 前不物化**；confirm 复核基线指纹，不符 → 409 `base_conflict` 零物化 | 串台改写：迟到拍板覆盖抢先修订 |
| workflow_* | `workflow_definition_versions` 行 = dag_json + content_sha256，**发布即冻结、版本行不可变** | `workflow_runs` 只持 (definition_id, definition_version)；`input_snapshot` 逐节点留痕 | run 随时可从版本行重装同一张图：**重算指纹 == 落库指纹**（可重建判据） | 跑动中被改即受影响（fde-v2 教训，T-W2 语义） |
| documents | 业务表（projects/tasks/members/gates/research…） | `build_document_snapshot` 纯读派生快照，**不落库** | 除 `captured_at` 采集时刻外逐位确定：任意时刻重跑复现（可重建） | 证据面/文档面错位：同一项目生成不同口径文档 |

横切第五面——**门禁证据候选**（`gates.evidence_candidates` JSON）：任务腿（T-G1）与 workflow 腿（T-W7）挂的候选都是**建议性数据**：claim_status 恒不动、永不写 `project_evidence`；物化唯一入口 = `submit_gate_evidence` 真人提交闸（命中指纹即剪除候选）。
