## 2. 完成的工作

| 模块 | 落点 | 关键语义 |
|---|---|---|
| **数据集三分** | `simulation/seeds.py::CASE_SPLIT` | 按**案例**切：A–D → train、E → regression、F → blind；同案例三变体**同属一个集**（否则对比失去可比性） |
| **split 校正** | `seeds.seed_scenarios` | 既有种子行的 split 就地校正（元数据修正，不改内容；内容不可变纪律不受影响） |
| **对比引擎** | `simulation/regression_runner.py` | 逐维度 Δ、硬性失败集合差异、成本 Δ、**泛化差**、过拟合闸 |
| **回归服务** | `simulation/regression_service.py` | 套件 → 基线组 → 候选组 → 落结果（幂等） |
| **改进覆盖载荷** | `improvement_proposals.override_json` | 候选改进**只在模拟域内**生效（`run_config`），生产配置零改动 |
| **提案纪律** | `improvement_service.create_proposal` | 改进**只许用 train 集**的失败发现（回归/盲测集的失败不得用于调参） |
| **API +6 路由** | `routes.py` | 套件 CRUD / 跑对比 / 结果清单与详情 |

### 2.1 数据集三分（按案例，不按变体）

| 集 | 案例 | 场景数 | 用途 |
|---|---|---|---|
| `train` | A 质量追溯、B 外贸获客、C 库存采购、D 设备维护 | 12 | **允许**用于提改进 |
| `regression` | E 排产 | 3 | 检退化 |
| `blind` | F 售后投诉 | 3 | 最终盲测（参考答案对被测方始终不可达） |

> **为什么按案例切**：同案例的三个客户行为变体必须同属一个集——否则「换个客户行为就换个数据集」会让前后对比的差异里混入「案例难度差」这一噪声。

### 2.2 前后对比的五项检查（不只看总分）

| 检查 | 指标 | 阈值 |
|---|---|---|
| 总分 | `total_delta` | \|Δ\| > 0.02 才算有意义 |
| 逐维度 | `dimension_deltas` / `regressed_dimensions` | 某维度 Δ < **−0.1** ⇒ 该维度退步 ⇒ 结论至少 `mixed` |
| 硬性失败 | `new_hard_failures` / `resolved_hard_failures` | **新增任一 HF ⇒ 结论不得为 improved** |
| 成本 | `cost_delta` | 一并回显（改进不许偷偷变贵） |
| **泛化差** | `generalization_gap = gain_train − gain_blind` | **> 0.15 且 train 增益显著 ⇒ `overfit_risk=True`** |

**结论取值**：`improved` / `regressed` / `mixed` / `no_change` / `inconclusive`。
过拟合 ⇒ 结果行带明确注记「**不得进入发布审批**」。

### 2.3 候选改进如何「生效」而不落地

```text
ImprovementProposal.override_json = {"run_config": {"probe_quality": 1.0}}
                     ↓ 只作用于模拟域内的运行参数
回归候选组 = 基线组参数 + override.run_config
```

这条链把「**验证改进效果**」与「**发布改进**」分成两道闸：回归只改模拟域的运行参数，**不触及任何生产 Prompt/Skill/Workflow/本体**；发布仍须人工在 V3.1 治理面执行（G5 的三重静态钉）。

### 7.1 本轮修掉的一处真实缺陷

**重复评估撞唯一约束 ⇒ 500**：`evaluate_run` 每次都**插入**评估行，而表上有
`UNIQUE(run_id, layer, evaluator_id, rubric_version)` ⇒ 对同一运行重跑评估（回归
对比必然如此：基线组与候选组会复用同一 run_key 的运行）直接撞约束、API 500。

修法：**评估幂等化**——同身份的行**更新**而非插入（规则版本变更仍新增行，历史
不改写）。这正是当初设计那条唯一约束时想要的行为，只是实现漏了 upsert 语义。

### 7.2 本轮修掉的两处测试自身缺陷（如实记账）

- 「同名套件唯一」用例未先建场景 ⇒ 套件创建先因「无场景」400，断言落错；
- 回归幂等用例的套件创建路径写错（`/simulation/regression/s`）⇒ 返回体取不到。

两处均为**测试写错**，非产品缺陷；已修正。

## 附录 · 诚实边界

- 回归集的「改进效果」是**模拟域内**的效果（`probe_quality` 这类参数），**不等于**真实 Prompt 改动在真实项目上的效果。
- 泛化差目前基于 1 个训练案例 vs 1 个盲测案例 ⇒ **统计意义弱**，只作**信号**不作**结论**。
- 真模型评估层未接线 ⇒ 三层机制实际跑的是「规则层 + 确定性替身 + 人工」。
- 本轮**未**做真实接口集成（G7/G8 的范围）；未用占位数据冒充。
