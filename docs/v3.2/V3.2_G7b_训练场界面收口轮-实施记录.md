# V3.2 G7b · 训练场界面收口轮——实施记录（2026-11-09）

> 起因：蔡工实测反馈三件事——①训练场里**找不到给 L-A/L-B 分歧拍板的地方**；②案例库点「编辑」后弹层**不能下滚、没有关闭按钮**；③编辑界面**排布混乱、一头雾水**。本轮三件全修，纯桌面零服务端。

## 1. 诊断（先勘误后动手）

| 用户观察 | 真因（代码级） | 定性 |
| --- | --- | --- |
| 找不到拍板地方 | L-C 终裁**服务端在位**（`POST /api/v1/simulation/runs/<id>/evaluation/human`）+ 桌面组件 `HumanReviewForm` 也写好——但 `SimulationRunDetail` 渲染 `<EvaluationReport>` 时**从未传 `onRecordHuman`** ⇒ 表单从未渲染 | **接线缺口**，非功能缺口 |
| 弹层不能下滚、没有关闭按钮 | `.dialog` 基类只有 `width/padding`，**无 `max-height`/`overflow`**；高表单弹层超出视口即被裁且不可滚，底部「取消/保存」落在视口外。仓库既有解法是各页加类（`.task-dialog`/`.file-version-dialog`/`.library-manager-dialog`…），训练场编辑器漏配；`Modal` 组件本身无 × 关闭钮（只有 Esc，不可发现） | **家族性坑的漏配实例** |
| 界面一头雾水 | 顶层十来个字段无分组无标题直接铺开；且六处 JSX 文案把 `**加粗**` 星号直出给用户；`simulation-warning/notice/error/hint` 四类状态行**零 CSS**（裸文本） | **信息架构 + 样式欠账** |

## 2. 修复清单（全部 additive，零既有类/既有调用方改动）

1. **`Modal` 可选 `className` + `dismissable`**（`components/ui/Modal.tsx`）：×关闭钮渲染在标题行右侧（`aria-label="关闭弹窗"`），busy 时与 Esc 同规锁闭；不传新 props 的既有弹窗行为零变化。
2. **`styles.css` 末尾新增块**（不改任何既有规则）：
   - `.dialog.simulation-scenario-dialog`：960px 宽 + `max-height: calc(100vh - 48px)` + `overflow-y: auto`（按 `.task-dialog` 先例的按页加类解法）；
   - sticky 底部操作条（取消/保存永远可见）；
   - `.ui-modal-heading` / `.ui-modal-close`（×钮走令牌，字阶钉过闸）；
   - 训练场四类状态行补样式（warning/notice/error/hint）+ `.simulation-human-form`。
3. **`ScenarioEditor` 三视角分区重排**：①基本资料 → ②客户可见面（Tester/Customer 视角）→ ③隐藏事实（按阶段披露，Customer/Judge 视角）→ ④评分侧（仅 Judge View），每区一句话说明「这一区写给谁看」。所有表单 label 文字保持不变（既有测试按 label 查询）。
4. **L-C 拍板接线**：`api.recordHumanEvaluation`（POST `…/evaluation/human`）+ RunDetail 权限门控（`admin`/`project_lead`，与服务端 403 同尺；其他角色只隐表单不隐告警）传 `onRecordHuman`；提交后**重拉评估报告**——human 层评估行与机器两行并列出现，`human_review_required` 随之解除（服务端语义：有人工行即不再标复核）。
5. **`EvaluationReport` 强化**：分歧告警按有无终裁权限分措辞（无权限者指路「项目负责人或管理员」）；`final=human` 时醒目回显「人工终裁已记录：<结论> · <分数>%（机器原行保留并列，未改写。）」；终裁表单标题改「人工抽检结论（L-C 终裁）」+ 理由必填说明 + UiButton 化。
6. **可发现性**：总览页 hint 写明拍板路径（运行台 → 选中运行 → 评估该运行 → 人工抽检结论）；六组件七处 JSX 直出星号清理。

**红线自证**：本轮只做入口与呈现——终裁动作必须是人（admin/project_lead）在界面上亲手提交；机器两行永不改写；模拟分数免责声明原样保留。

## 4. 流程事故（如实登记）

脚本化补丁一轮以**相对路径**执行，而 shell 工具每条命令后把 cwd 重置回主树 `D:\test\fde-workbench` ⇒ 六文件改动**误落主树**（并发会话地盘）。处置：逐文件 diff 核验「只含本轮 hunks」→ 补丁存档 → `git checkout --` **精确还原六个文件**（主树 `styles.css` 的既有脏文件属品牌/CSS 会话，未触碰）→ 同一补丁落回 V3.2 隔离工作树重验全绿。

**教训入档**：批量脚本补丁必须先 `cd` 到目标工作树或全部用绝对路径；shell 工具的 cwd 重置是每命令后的常态不是异常。此条已并入并发会话纪律记忆。

## 5. 拍板操作路径（给蔡工的指引）

1. 桌面端 → 模拟训练场 → **运行台**；
2. 左侧选中要终裁的运行（当前待终裁：run `91d00a0f…`，CASE-A-QUALITY-TRACE，真实执行面）；
3. 右侧「评估报告」会显示黄色告警「需人工终裁：规则层与模型层分歧 0.25（阈值 0.2）」；
4. 滚到报告底部「**人工抽检结论（L-C 终裁）**」：选结论（通过/有条件通过/未通过/硬性失败/结论不可靠）、给总分（0–1）、**理由必填** → 「提交人工终裁」；
5. 提交后报告顶部回显「人工终裁已记录」；机器两行（规则层 0.5504 hard_fail／模型层 0.8022 pass）原样并列保留，随时可查。

权限：admin / project_lead 可终裁（服务端同尺 403 兜底）；需要先用有权限的账号登录（审阅人=蔡工本人，账号分离先例按 V3.1 pilot 约定）。
