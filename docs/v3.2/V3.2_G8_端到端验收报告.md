**数据集三分实测**：A–D → train（12）、E → regression（3）、F → blind（3）。

### 2.1 一条必须写进报告的诚实观察（G8 初测 → G9 复测）

**G8 初测（校准前）**：18 次运行得分**完全相同（0.735）**。根因是规则层用
「Rubric 文本 ⊆ 产物文本」的**精确匹配**判覆盖——Rubric 写的是「应当识别出什么」，
产物写的是「实际说了什么」，措辞天然不同 ⇒ 精确匹配恒为 0 ⇒ 判据恒为 0。

**G9 校准后（复测）**：覆盖判定改走**确定性字面重叠**（`simulation/textmatch.py`，
阈值 0.25，对 6 案例的 22 条 `must_identify` 实测标定，命中率 16/22）。复测结果：

- 18 次运行出现 **7 个不同分**（0.735 / 0.7983 / 0.8300 / 0.8490 / 0.8617 / 0.8775 / 0.9250）；
- 平均 **0.8314**；verdict 15 pass + 3 conditional；
- 失败发现从 36 降到 **16**（规则层现在认得出「已披露的根因」）。

⇒ **G8 §2.1 记录的校准缺口已闭合**：评估器现在能分辨「问得深 ↔ 知道得多 ↔ 产出更全」。
**仍存的口径限制**（如实记账）：
1. 字面重叠**不是语义理解**——同义改写仍会漏判（剩余 6/22 未命中）；语义层面由
   模型层（G9 已接线）承担。
2. `must_produce`（交付物类）**不走**字面匹配——它在**交付正文**上判（与事实类分
   口径），否则会把「提到客户画像」误判成「产出了线索采集流程」。
3. 分数反映**模拟域**的结构与覆盖度，**不是**真实交付质量。

## 5. 本轮实测修掉的两处真实缺陷

| # | 缺陷 | 症状 | 修法 |
|---|---|---|---|
| 1 | **注入故障被误判为越界** | 场景自带的 `fault_injection`（如 CASE-B 的 `sim.mail.send` 权限故障）让运行直接落 `failed_hard`——**场景机制被当成安全越界** | 环境层区分 `kind ∈ ok / boundary / fault`：只有 `boundary`（调用非 `sim.*` 工具）进 `rejected_calls` 并判硬失败；`fault` 只记录（新增 `tool_failures` 计数） |
| 2 | **重评撞唯一约束 ⇒ 500** | `evaluate_run` 每次插入评估行 ⇒ 对同一运行重评（回归对比必然如此）撞 `UNIQUE(run_id, layer, evaluator_id, rubric_version)` | 评估**幂等化**：同身份 upsert；规则版本变更仍新增行 |
