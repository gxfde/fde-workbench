## 1. 本轮目标

让一个模拟案例能够驱动 FDE 执行面完成**一次完整交付模拟**，并把全过程（工具调用、状态变化、产物、证据、越界拦截）**全量留痕**，可逐条回放与复算。

### 2.1 七相位流程

```text
setup → interview → analysis → design → implementation → validation → wrapup
```

每个相位至少一条 Trace；`interview` 阶段逐轮记录顾问问、客户答、**披露事件**（`hidden_fact_disclosed`，含触发方式：命中关键词 / 客户升级）。

### 2.2 「问得深 ↔ 知道得多 ↔ 产出更全」是可测的

mock 模式把「顾问追问质量」折成一个**可控参数** `probe_quality`（0–1）：

| probe_quality | 顾问行为 | 披露 | 产物 |
|---|---|---|---|
| 0.0 | 只问泛问（不含任何事实关键词） | 0 条 | 需求/验收退化为占位 |
| 1.0 | 总问命中关键词的目标化问题 | 命中即披露 | 需求/验收/根因随披露数增长 |

这条链路是 G4 评估与 G6 回归的**信号源**。

> **诚实边界（写进评估报告 meta）**：mock 模式的分数**不代表真实 Agent 的交付质量**。它衡量的是「训练场机制是否按预期把这条链路跑通」。真实执行面接线后，结论才具备 Agent 质量含义。

### 2.3 客户模拟器的「不编造」四重保证

1. 能说的内容只来自场景（`hidden.facts` + `visible`）；
2. 关键词命中才披露，**未命中不披露**（沉默即信号）；
3. 未命中时走**受控非应答模板**（不含任何事实内容）；
4. `disclosure_stage` 阶段闸：分析阶段前不许把结论说完；`complex` 变体可**主动升级**（被忽视 N 轮后客户自己补充）。

## 6. API 变化（+7 路由，不进 api_catalog）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/v1/simulation/runs` | 运行列表（scenario_id/status/split 过滤） |
| POST | `/api/v1/simulation/runs` | 创建（`execute=true` 立即执行）；同键重放返回既有运行 |
| GET | `/api/v1/simulation/runs/<id>` | 运行详情 |
| POST | `/api/v1/simulation/runs/<id>/execute` | 执行（同步）；真实面不可用 ⇒ 409 `adapter_unavailable` |
| POST | `/api/v1/simulation/runs/<id>/cancel` | 取消（终态 409） |
| POST | `/api/v1/simulation/runs/<id>/retry` | 重试（attempt+1 派生新键；`failed_hard` 409） |
| GET | `/api/v1/simulation/runs/<id>/trace` | Trace 分页（seq 游标） |

**幂等键**：`run_key = scenario_key:variant:vN:seedS:aA:cfg<配置指纹8位>`。
配置指纹进键 ⇒ **「改了访谈参数却被当成同一次运行」被堵死**（本轮实测踩到并修）。

### 7.1 本轮实测修掉的四处问题

| # | 问题 | 症状 | 修法 |
|---|---|---|---|
| 1 | **静默复用同一次运行** | 改了 `probe_quality`/`max_rounds` 再跑，返回旧运行（配置被吞） | `run_key` 加**配置指纹**（sha256 前 8 位）⇒ 同配置同 seed 幂等，配置变了即另一条运行 |
| 2 | **越界调用未接住** | 环境拦了工具，但异常冒到 API ⇒ 500、运行卡在 `running` | 执行器捕获 `SimulationBoundaryViolation` ⇒ 运行直接落 `failed_hard` + `error_json` + Trace 留证 |
| 3 | **`adapters/__init__.py` 漏 import `Any`** | 整个模块导入即 `NameError` | 补 import |
| 4 | **迁移用例泄漏 projects 行** | 本用例建的 `projects` 行残留 ⇒ 后续重跑基线迁移的用例撞 `projects.enterprise_code` 的 NOT NULL 约束（该列无默认值，只在空表时可加）⇒ 13 个用例连环红 | 用例**自清理**（`cleanup_seeded_rows` + `finally` 兜底）——**共享测试库的一条隐性地雷** |

> 教训 4 与仓库既有教训同族（#109 的「吞错不滚回」）：**共享测试库里，一次用例的残留会污染其后所有用例**。新写迁移用例必须自清理。

## 11. 下一轮目标（G4 独立评估引擎）

1. **L-A 确定性规则**（`evaluation_rules.py`）：七维度 + 7 条硬性失败规则（HF-01..07）；**只有 L-A 有权判硬性失败**。
2. **评分聚合**：无 `evidence_refs` 的分项不入账（记 `unverified`）；`unverified` 占比 >20% ⇒ `inconclusive`；HF 命中 ⇒ `hard_fail`。
3. **L-B 独立模型评估**：独立评估 Agent，**不读实施方自评**；与 L-A **并列呈现不取平均**；分歧超阈值 ⇒ 触发 L-C。
4. **L-C 人工抽检**：高风险/低分/分歧三类触发；人工结论**覆盖**机器结论但**保留机器原行**（留痕）。
5. **评估表** `simulation_evaluations`（含 rubric_version、层级、证据引用、分项得分）。
6. **评估报告**：每个得分可下钻到 Trace 段或产物；`meta` 段回显 `adapter_mode` 与「合成结果不冒充真实业务数据」的限定语。

## 附录 · 诚实边界

- **未接真实执行面**：本轮的模拟产出由 Mock 适配器生成。**其分数不代表真实 Agent 的交付质量**。
- Mock 的「顾问」是**脚本化**的（`probe_quality` 控制追问命中率），不是模型。
- 工具白名单已强制，但**虚拟工具本身返回的是场景种子数据**——真实业务系统的行为复杂度未被覆盖。
- 本轮**未**实现评估、失败分析、回归——G4–G6 的范围；未用占位数据冒充。
