## 1. 本轮目标

把 G2–G6 的服务端能力变成**可操作的训练场工作台**：案例、运行、Trace、评估、失败、提案、回归七个面齐备，且每个面都覆盖 loading / empty / error / 权限态。

## 2. 完成的工作

| 页面 | 组件 | 内容 |
|---|---|---|
| 总览 | `SimulationDashboard.tsx`（G2 已有，G7 扩充语义） | 案例分支数、案例数、三种客户行为计数、数据集分布 |
| 案例库 | `ScenarioLibrary.tsx`（G2 已有） | 过滤（客户行为/数据集/状态/关键字）、新建/编辑/复制/归档/导出 |
| 场景编辑器 | `ScenarioEditor.tsx`（G2 已有） | 客户背景、简报、约束、隐藏事实（阶段+探针）、**评分侧**三段（明确标注不暴露给被测方） |
| **运行台** | `SimulationRunDetail.tsx`（新） | 左：运行列表（按数据集/状态过滤、发起/取消）；右：选中运行的 **Trace 时序 + 评估报告 + 失败分析** |
| **评估报告** | `EvaluationReport.tsx`（新） | 三层**并列**呈现、维度分条、判据下钻（含「无证据未入账」提示）、硬性失败单列、**人工抽检表单** |
| **失败分析** | `FailureAnalysis.tsx`（新） | 按严重度排序、根因置信度徽标（已确认/较可能/待人工确认）、证据条数、**「可生成改进提案」提示** |
| **改进提案** | `ImprovementProposals.tsx`（新） | 提案清单、目标/版本/变更摘要/回归计划、审批（密码+理由）、**「审批 ≠ 发布」明示** |
| **回归与盲测** | `RegressionDashboard.tsx`（新） | 套件清单、跑对比、**过拟合告警**、**退步维度**、硬性失败差异、成本 Δ、泛化差 |

**页面外壳**：`SimulationLabPage.tsx` 五分区（总览 / 案例库 / 运行台 / 改进提案 / 回归与盲测）。

### 2.1 界面必须讲清的三件事（不是文案，是纪律）

| 纪律 | 界面落点 |
|---|---|
| **模拟结果不等于真实交付质量** | 评估报告页顶部固定回显 meta 里的限定语（rubric 版本 + 执行面 + disclaimer） |
| **模型层可能是 stub** | 模型层卡片显式显示 `mode` 与「stub 模式：确定性替身，非真模型评分」 |
| **审批 ≠ 发布** | 提案页顶部与每条提案的底部都写明「落地由人工在治理面执行」；按钮文案即「批准（不发布）」 |

## 8. 安全检查

| 项 | 状态 |
|---|---|
| 界面绕过服务端闸 | **无**——所有写动作走服务端；前端只做**读面**契约校验（`isScenarioDto` 等），不做业务判定 |
| 密码在界面留存 | **不**——审批密码只随请求体递交，不入状态、不落盘 |
| 越权可见 | 服务端按能力档返回 403；界面**原样呈现**错误文案，不伪装成空列表 |
| 重复提交 | 写动作走 `AsyncButton`（busy 态禁用）+ 服务端幂等键 |

## 附录 · 诚实边界

- 本轮**只做界面**：未新增任何后端能力，未引入静态 mock 冒充真实数据（所有面板都消费真实 API，接口不可用时呈现错误态）。
- 界面**未做无障碍专项审计**（键盘遍历、读屏顺序、对比度）——沿用既有组件原语，但未逐项验证；留待 UI 专项轮。
- 训练场的「跑一次」按钮目前用案例库第一个场景作默认目标；**按指定案例发起**的入口在 G8 的运行台收口里补齐。
