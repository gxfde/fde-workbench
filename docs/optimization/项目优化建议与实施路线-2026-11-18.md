## 2. 六项优化建议

### O1：真实试用与主流程（业务最高优先级）

验证一条完整路径：注册验证→首次登录→建立代号项目→调研→生成并人工确认方案→提交可验收成果。

先记录首次有用成果耗时、人工介入点、返工原因、再次使用意愿，再按观察改入口、默认值、提示和错误恢复。角色首页、下一步指引、示例项目都是待验证方案，不预设必须重做导航。小规模观察不冒充统计显著性。

验收：每条观察有匿名场景、任务结果、介入原因、成果指针；未独立完成不得计入独立完成；协助完成单列，失败和放弃保留在已尝试分母。OWNER负责招募和同意，AI不外发邀请。材料就绪不等于真实试用通过。

### O2：发布一致性与恢复（工程最高优先级）

顺序：只读候选版本核验→部署入口互斥→固定镜像/迁移→隔离恢复。复用takeover_check和三验，不另建配置真相。

发布记录分别记录预期和实际提交、镜像摘要、迁移头、配置版本标识、桌面包指纹。配置不记录密钥值或可反推弱口令的摘要。锁按实际Docker目标与Compose项目协调，不能按工作树各锁各的；盘清全部入口并承认旁路限制。

父进程退出但部署子进程仍存活时不得误回收锁。生产代码与迁移来自同一版本。恢复须验证数据、指针和加密配置并计时，旧镜像切回不等于数据库回滚。先隔离验证，再按既有授权执行生产切换。

### O3：AI净收益与跨场景验证

复用指标和审计，补人工总投入、首次验收通过率、返工时间、每份验收成果成本、接管原因。失败和重试计入成本，演练不混真实分母；同类任务固定版本与判据。指标先用于内部改进，不自动用于项目Gate或人员考核。

跨场景族复测保留失败、排除理由和退化；证据不足保持未知。不得把单点改善升为普遍有效。标准答案隔离不变；付费模型、生产agent、覆层发布、扩权和新阈值走现有授权链。

### O4：容量与可靠性

四条用户链：登录并打开项目、保存调研/方案、后台生成到终态、证据提交及授权审批。分别记录请求、排队、执行、人工等待、失败和恢复。

先在隔离栈用合成负载测基线，再按试用规模约定SLO；不预设任意百分比，不向生产压测。报表聚合先测耗时与内存再改，权限、时间窗、排除和分母语义必须保持。

### O5：工程维护

保持Flask/SQLAlchemy/React/Electron。随实际改动收敛接口契约、消减类型债务；慢测试和flake先定位再修，完整集成门禁保持。写入恢复体验对接现有UX线，不重复建写通道、并发框架或代切严格。无测量证据不做全仓重构。

### O6：文档与规则减负

AGENTS保留必须遵守的边界和权威入口；历史按用途归档，现役红线不擅删。数量来自现测机器清单；实现、部署、验收分开。两份手册同源，不写未经授权的自动记忆。

配置清单需要随轮纠错：注册BLOCKED的FROM/允许域示例使用主域，但文字要求主域不发信；REVIEW_ENTRIES留空与“交付者/合作商仍审核”的说明也须对照配置解析与测试核实。先确认有效语义，再改文档，不擅改部署配置。

## 3. 关键假设与停止条件

| 假设 | 最小验证 | 改线条件 |
|---|---|---|
| 用户主要卡在操作 | 无讲解完成任务并记录介入 | 卡在价值或资料时，暂停导航重做 |
| 锁能减少覆盖 | 两工作树竞争同一目标并核所有入口 | 旁路/失联子进程未解决，不宣称全局保护 |
| AI改善是净收益 | 同类任务比较人工、返工、模型成本 | 质量退化或无净改善，不扩大应用 |
| 资源能支持试用 | 隔离逐级负载与排队曲线 | 达登记资源/时限停止，不能影响主栈 |
| 文档收敛能减负 | 下一会话可定位唯一现役口径 | 丢失红线/审计证据则回退 |

## 4. 分轮路线

| 轮次 | 工作包 | 完成证据 |
|---|---|---|
| R0 | 本路线、leader任务书、进度、待裁决、试用观察模板 | 链接/长度/覆盖核验，在途盘点 |
| R1a | 只读发布候选核验CLI与真实临时Git仓测试 | 干净固定SHA/单头通过，错SHA/脏树/断图/多头拒绝，CI接线 |
| R1b | 部署互斥与发布身份设计、隔离实现 | 跨树竞争、子失败、父退出反例，既有三验不退 |
| R1c | 固定发布产物和恢复 | 隔离恢复计时、数据与加密配置验证；生产守接管闸 |
| R2 | 试用观察、配置清单纠错、卡点优化 | 真实观察→优先卡点→复验；OWNER前提不以备料销项 |
| R3 | 人工基线、AI净收益与跨场景回归 | 同口径对照、失败计入、未知不升档 |
| R4 | 容量基线与实测热点优化 | 相同负载前后对比，权限/统计语义无回归 |
| R5 | 契约、类型、文档随轮收敛 | 零新增债务、手册同源，无第二真相 |

R1a细规格见[发布候选核验实施规格](R1a-发布候选核验-实施规格.md)。R1a仅核候选输入，不部署、不锁Docker、不证明活体。后续轮先形成白名单、接口、验收、回退的小规格再编码。OWNER前提只阻断相关项；既有UX在途改动不重复认领。

## 5. 状态与完成规则

每轮记录实现、审查测试、PR/CI/合并、部署、用户验收。全部适用轮有证据通过或由用户明确取消，才可把总Goal标complete。分轮成果可以交付，总Goal不能因材料齐全而结束。
