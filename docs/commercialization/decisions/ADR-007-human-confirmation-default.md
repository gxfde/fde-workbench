# ADR-007：关键流转默认需人工确认——高风险写双闸模式与人工接管路径

- **状态：** Accepted（G2 成文，2026-11-08；G0 §H 实测驱动——自动化水平实测样本=0）
- **消解：** 任务书 §0.5 三条硬约束之落地形态；G0 phase-status「ADR-007 归 G 阶段设计轮成文」挂账销号
- **基线：** fork/main `7c32736`

## 1. 背景

交付智能化等级（**平台**，越大越自动化，BP §1.3a）当前书面评级 **L2+（向 L3 演进中）**；G0 活库实测：`agent_runs`/`solutions`/`workflow_runs`/`simulation_runs` 全 0——AI 草稿采纳率、人工接管频次均 `insufficient_data`。任务书 §0.5 据此规定：在取得实测数据前，**关键流转（权益变更、额度扣减、席位激活、商机归属确认、区域升级）按「默认需人工确认」实现**。

## 2. 裁决

1. **高风险写 = admin 门 + 单次显式授权（密码确认）双闸**：服务层 `_require_admin`（403）+ `confirm_password` 必填（缺 400／错 403 `invalid_password`，`auth/passwords.verify_password` 单点）。G1 六条权益写路由与 G2 额度授予/完成路由均按此模式。
2. **AI 产出走草稿/建议位，无直写入口**：商业化域的治理面路由**全不进 api_catalog**（AI 不可调用）——人工确认通道是唯一写路径；系统可在读面呈现建议，判定权在人。
3. **人工接管路径沿既有模式，不建第二套**：`handoff_run` 的 `handoff_user_id` + signoff checkpoint + `operation_events` 事件是全系统唯一接管承载；商业化域写操作逐动作落 `operation_events`（Actor/前后状态/request_id），可审计可回放。
4. **自我动作例外**：企业用户对自己主体的「诊断启动/企业确认」是当事人自证动作（非高风险治理写），走认证用户路由 + 事件留痕，不需 admin 密码——但完成标记（六项判据判定）仍是交付咨询环节的治理写（admin+密码）。
5. **实测后复审触发器**：首批真实 run 数据积累后（agent_runs 非零且采纳率埋点 GAP-15 有数），按 BP §1.3a 证据口径复审智能化评级与确认点密度——在此之前本 ADR 的「默认人工确认」不放松。

## 3. 理由

- **交付智能化等级**（平台，越大越自动化，BP §1.3a）的 **L3** 定义即「AI 出初稿、人审核后交付」——人工确认不是能力缺失而是形态本身（§0.5）；实测样本=0 时放松确认等于把「未验证」当「已验证」。
- 密码确认双闸是仓库既有惯例（方案归档、扩展治理、Skill 发布四闸、G1 权益面），零新模式零新依赖。

## 4. 与其他 ADR 的关系

- ADR-002/004 的「高风险写」定义引用本 ADR §2.1 双闸。
- ADR-005（区域商业化闸，G5 成文）的开关条件属更高一级闸（合规条件），与本 ADR 的操作级确认叠加。
