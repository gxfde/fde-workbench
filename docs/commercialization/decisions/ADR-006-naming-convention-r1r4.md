# ADR-006：角色分层命名规范 R1–R4 与 L 编号引用纪律

- **状态：** Accepted（G0 裁决，2026-11-08）
- **消解歧义：** 任务书 §0.4（L 编号四套同名不同义 → 角色分层改用 R1–R4）
- **基线：** `eee317c`

## 1. 背景（实测）

全仓存在多套「L/level」同名概念，主语与刻度方向各异（完整六套清单与锚点见 ADR-001 §3.2）：交付智能化等级（平台）/ 交付能力等级（人）/ 降级链状态（单次运行）/ 角色分层（组织职级）/ AI 访问档位 / 催款级别。商业原文还用「L2 实战营 9800／L3 陪跑营 19800」指**培训营档位**，与上述全部无关。若角色分层继续用 L 编号入库，将出现第五套 L 值域，任何一句「L3」都需语境才能解码。

## 2. 裁决（已拍板，任务书 §0.4 第六批 2026-11-08）

1. **系统内角色分层一律用 R1–R4**：`R1` 企业／`R2` 创业者／`R3` 交付者／`R4` 区域合作商；可空=未分层。**代码与迁移中不出现以 L 开头的角色枚举值**。
2. **既有各套 L 零改动**：`fde_profiles.level`（交付能力等级：人，越大越资深）、`agent_runs.fallback_level`（降级链状态：单次运行，越大越不自动化，不可删）、智能化等级（BP 文档口径，无代码字段）的名称、值域、语义全部保持。
3. **对外 L0–L4 商业编号仅存于映射表**（ADR-001 §2.4）：从角色＋订阅/认证状态推导，映射表是唯一转换入口；代码中不得散落 L 编号换算。
4. **培训营档位不用 L 编号指代**：代码与文档统一称「实战营」「陪跑营」。
5. **三要素纪律**：凡引用 L 编号，必须同时写明「**哪一套 + 主语 + 方向**」，如「交付能力等级（人，越大越资深）」「降级链状态（单次运行，越大越不自动化）」「交付智能化等级（平台，越大越自动化）」——不得只写 L1/L2/L3。评审按此条否决歧义引用。
6. `fallback_level` 的数值**不得**用于推断智能化等级（两套刻度方向相反）；智能化评级升降格按 BP §1.3a 证据口径走（G0 实测样本=0 ⇒ 维持 L2+，见 00-baseline-audit §H）。

## 3. 理由

- R 前缀在代码中零歧义（仓内无既有 R 系枚举，G0 grep 确认无冲突）；映射表把「对外怎么叫」收敛为单点数据，商业口径调整不再改代码。
- 三要素纪律是文档面防线：本仓库历史上「12 提交」「155→156」等口径漂移反复发生（AGENTS.md 家族性教训），数字/编号类引用必须自带限定语。

## 4. 后果

- G1+ 所有新表/新列/新枚举遵循本规范；映射表实现随 G1。
- 文档评审新增一条否决项：歧义 L 引用（缺三要素）必须改写后才可合入。
- 对外物料（官网/BP）中的 L 编号属营销口径，不由本仓代码承载；本仓映射表只服务系统内展示需要。
