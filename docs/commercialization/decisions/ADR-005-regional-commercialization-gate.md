# ADR-005：区域商业化闸——四阶段阶梯与售卖能力默认关闭

- **状态：** Accepted（G5 成文，2026-11-09）
- **消解：** 任务书 §9（T-12a，**不含 T-12b**）的落地歧义；G0 基线审计预留的「区域商业化闸」裁决位
- **基线：** fork/main `2538a02`（G4 收口态）
- **配套成文规则：** `docs/commercialization/rules/regional-partner-program-rules.md`（**规则唯一成文处**）

## 1. 背景（实测）

- G0 基线审计：区域伙伴**无任何概念**（GAP-12）——本域从零新建。
- BP v4.0 已有三档定价定案（T1 29800／T2 59800／T3 98000，v4.0 终版经蔡工拍板），**但对外售卖是受监管约束的商业行为**——任务书 §9 硬约束：本期不做 T-12b（对外收费签约能力），售卖能力**默认关闭**，开关开启条件绑定合规条件清单已签署。
- 合规条件来自《商业特许经营管理条例》第七、八、十二、二十一条及《商业特许经营信息披露管理办法》第四条（公开规范原文摘录，事实引用）；**「本模式是否被认定为特许经营」是法律判断，须律师出具意见——本期不预设结论**。
- G4 已落商机归属链路（ADR-009）与「规则未配置 ⇒ fail-closed」纪律；G3 已落收入科目层（`project_share` 行）；两者被本域**引用**而不重建。

## 2. 裁决

1. **四阶段按闭集落地**（成文规则 §2）：`city_observer`（免费申请）→ `city_service`（按项目结算，一单一结，不设固定年费）→ `formal_partner`（三档年费）→ `regional_agent`（**本期不启用，保留位置并注明「暂不启用」**）。阶段注记是读面派生（代码常量单点），不是数据列。
2. **售卖开关＝单行全局闸，默认 closed**：`regional_sale_gate` 迁移播种一行 `closed`；开启＝关键流转（admin 门＋密码确认双闸，ADR-007 §2.1）＋合规条件清单四项签署证据（指针＋sha256＋签署时刻）**先行登记齐备**——CHECK `ck_regional_sale_gate_opened_complete` 结构性排除缺件开门。
3. **「无任何代码路径可在开关未开启时对外收费签约」＝结构性保证**：进入 `formal_partner`（即对外收费签约的开始）的唯一服务原语 `promote_partner` **第一步过 `require_sale_gate_open`**（闸关 ⇒ 409 `regional_sale_gate_closed`）；档位目录（`regional_partner_tiers`）只是定价定案数据，**目录存在 ≠ 可以售卖**。反例与结构性用例钉死（含源码扫描钉：`formal_partner` 写点唯一且在过闸函数内）。
4. **合规条件四项登记 ≠ 开启**：`register_gate_condition` 只登记证据；开启是独立动作且**开关已开启后条件不可再变更**（409 `gate_already_opened`）。
5. **前两阶段不授予独家区域权**：CHECK `ck_regional_partners_first_two_stages_no_exclusive` 结构性联锁＋服务层 409 `exclusive_not_allowed` 双重封死；独家权只在 `formal_partner` 可声明。
6. **区域代理「暂不启用」＝能力边界**：`regional_agent` 在闭集保留位置，但服务层对任何进入动作显式 409 `regional_agent_not_enabled`——不是数据状态，是没有写路径。
7. **城市服务伙伴按项目结算（一单一结）**：`regional_service_settlements` 引用既有 G3 科目层 `project_share` 行（不建第二套结算引擎），一个科目行至多关联一次，科目行归属必须与结算项目一致；正式档不得写本表（409 `settlement_channel_mismatch`——两档收费形态互斥）。
8. **试运营升级指标与首期金额本期不定数**：原文示例（首期 9800／90 天／补 20000）**不得作为合同条款或既定指标**——本仓任何代码、迁移、种子、规则槽位均不落这些数值（哨兵用例钉死）；规则文件机器可读块中该槽显式 `status: "unset"`。
9. **三档定价以 BP v4.0 为唯一基准**：T1 29800/15 席/转赠 7、T2 59800/30 席/转赠 15、T3 98000/50 席/转赠 25，迁移播种进目录行（`basis_reference` 记基准指针）；机器闸把规则文件 JSON 块 ↔ 代码常量 ↔ 迁移种子三方钉死。
10. **真实身份材料零入库**：只登伙伴代号与区域名；升级/条件/结算的书面依据一律指针 + sha256（AGENTS 红线）。

## 3. 理由

- **开关做成结构性 CHECK 而不是纯应用层判断**：缺件开门的后果是监管风险，最强可执行形态是数据库层就不可能（`opened ⇒ 四项齐备`）——与 G4「保护中必有到期（排除永久锁定）」同款哲学。
- **`require_sale_gate_open` 作为唯一闸门而不是逐路由散布判断**：闸门单点＝审计单点；源码扫描钉把「唯一写点在过闸函数内」机械化为测试，防未来新增路由绕闸。
- **目录与能力分离**：定价定案（BP v4.0 已拍板）可以落目录供内部对齐；**售卖能力**是另一件事，被闸独立控制——「有价目表」与「能签约」不混同。
- **前两阶段无独家权做成 CHECK**：独家承诺是商业与法律双重高风险动作，结构性排除比判据校验可靠（判据会漏、CHECK 不会）。
- **区域代理不做成「禁用状态列」**：状态列会诱导未来加一个「启用」开关就把省级代理放开；「无写路径 + 显式 409」把「暂不启用」固化为本期能力边界，放开须改代码（＝有 PR、有评审、有 CI）。

## 4. 后果

- 新增四表（`regional_partner_tiers` / `regional_partners` / `regional_sale_gate` / `regional_service_settlements`）＋迁移（55→56 rev，单链单头 `b3e8a6c2d4f7`）；商业路由 +9（427→436；全部不进 api_catalog）。
- 对外收费签约能力**本期为零**（闸关闭＋无签约服务原语）；T-12b 留待合规条件齐备后的独立轮次。
- ADR-007 §2.5 的「更高一级闸（合规条件）」就此落地：操作级确认（密码）之上叠加合规级闸（四项签署证据）。
- 数值待拍板项（任务书 §17）：试运营升级指标、首期金额——配置槽显式 `unset`，成文后由业务轮填实。
