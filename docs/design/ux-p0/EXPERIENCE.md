# 交付工作台 UI/UX 优化方案 · 评审草案

**建议先做两件事：先防止误写、误采纳和不可逆误操作，再让四类用户从待办直达下一步。** 保留现有交付规则、项目链接和视觉体系，不另建一套任务或证据台账。

## 1. Foundation · 范围与证据

- 主范围：Windows 桌面端，覆盖售前、方案与报价、派单/接单、日常执行、评审、门禁与结项。登录后的同构网页回归共用改动；手机端、公网诊断/注册、真实资金结算和平台运维改版不在本轮。
- 依据：文档中心《交付工作台升级 PRD v1.0 定稿》§2、§5、[11-17 贯通验收报告](https://github.com/caishide/fde-workbench/blob/812420186853f75ae1c9bfd66479b2a19aeb839f/docs/audit/%E8%B4%AF%E9%80%9A%E9%AA%8C%E6%94%B6%E6%8A%A5%E5%91%8A-%E6%8E%A5%E5%8D%95%E5%88%B0%E4%BA%A4%E4%BB%98-2026-11-17.md#L11)、桌面源码和服务端权限。贯通报告证明合成案例的 API 机制走通，不证明界面易用、真实客户已使用或已完成结算。报告中的模板部署缺口已修，方案补的是失败识别与恢复反馈。抢单和商机功能保留原有城市、席位及开关条件，不因导航重组默认开放。
- 下文用「源码确认」标识现有界面行为，用「待走查」标识尚无使用数据的判断。未做真人访谈、GUI 实测或性能基线。本文和 [DESIGN.md](./DESIGN.md) 为评审草案，不是已实施结论；文字布局示意与正文冲突时，以本文为准。
- 体验分组不改数据模型、授权或状态机。项目可见性和写权限继续由服务端判定；登录身份、企业归属、项目成员关系、AI 能力、商业席位分别判断。限制范围内的真人确权、审批、终审、门禁裁定和交付登记不可由 AI 代做。

## 2. 用户角色与高频场景

| 业务角色 | 班次中反复做什么 | 建议默认入口与首要动作 | 权限边界 |
|---|---|---|---|
| 创业者／售前协作者 | 把客户诉求整理成调研对象和问题清单；核对来源；将已确认内容交给负责人推进方案 | 调研待办或最近调研；从项目直达「调研」，快速返回原记录 | 仅使用已授权的项目、表单和 AI 能力；能起草不等于能确认方案或签字。报备看本人有效席位，不靠角色推断。 |
| 项目负责人／资深 FDE | 建项目、盯卡闸、确认方案与报价、协调接单与交付、核对证据和产物 | 任务中心「我负责／待我处理」；项目总览先看阻塞和下一步 | 系统角色是 `project_lead` 不等于可管理所有项目；在本人负责项目及既有授权内执行。企业自助负责人按自身能力使用，不等同平台运营。 |
| 交付工程师 | 看邀约、本人接单、查首批任务、更新状态与阻塞、在授权下补材料 | 任务中心「我的任务」和「待接单」；接单回执直达项目任务 | `fde_engineer` 接单后按成员和指派范围更新本人负责或协作任务的执行字段；管理字段、报价、判门、交付登记不随接单授予。 |
| 平台管理员／运营 | 看待指派、待复核以及卡在交接或结项的事项；执行平台专属治理动作 | 任务中心优先看可处理队列；低频配置收在「平台管理」 | 平台身份、系统角色和动作专属闸照旧；最终交付登记仅按现行管理员授权执行。 |
| 授权查看者（辅助） | 查看项目进展、门禁结论或已授权的交付清单 | 项目列表 → 项目总览；只读，无授权时不显示对象 | `viewer` 不自动看到所有项目或资料；对客户或企业成员，不以「查看者」来假设对外发布能力。 |

高频顺序是**先找自己该处理什么，再进入对象所在页面办事，办完回原列表**。工程师和负责人对这一顺序的偏好仍需真人验证；默认入口是设计建议，不用角色自动跳过显式深链。

## 4. Information Architecture · 优化后的页面结构

### 全局：复用任务中心，不新建平行首页

| 一级入口 | 二级页面／默认视图 | 首屏内容与直达去向 |
|---|---|---|
| 任务中心 | 我的任务、待我审批；待接单先提供「我的接单」快捷入口；需要时再显示负责人负责队列 | 第一屏为可执行队列；优先显示临期、阻塞和书面待办。按服务端范围读取，未知计数不显示为 0；不发明全局跨角色总数。 |
| 项目 | 项目列表、项目详情；有权限者可新建 | 列表保留现有筛选、分页与原项目链接。返回恢复原筛选/页码/焦点；筛选无结果与没有可见项目分开。查看者直接从这里起步。 |
| 派单与接单 | 派单池、我的接单、派单管理等现有子页 | 从任务中心到接单收件箱只需一步；派单操作仍在当前派单域。「派单包」只作展示别名，不改业务对象或字段。 |
| 商务与企业 | 线索池、企业空间；项目级报价留在项目内 | 只有原规定范围的入口才出现。诊断线索、渠道商机与项目立项后的机会主体各用原名和来源，不合并或冒充同一台账。 |
| 工具与帮助 | 翻译器、集成桥、训练场、帮助，按权限或开关 | 项目内工具仍可就地打开；管理员配置不混入常用动作。 |
| 平台管理 | 配置、用户、商业化运维、AI 与扩展、模板；指标报表保留平台侧角色范围，试点报告仅管理员 | 对已有权限者显示；负责人原可读指标不因挪组失权。账号、版本及退出仍在现有账户区。 |

初始进入时，显式合法深链优先。P1 先加快捷入口，不立即强制改所有人的登录落点；真人试用后决定交付侧无深链默认进任务中心，查看者仍以项目为起点。旧书签、帮助链接和浏览器前进/后退都保留。

### 项目：业务分组不等于审批顺序

保留原 13 个标签 ID，新增分组只改变入口呈现。执行与验收可交错，不把导航做成强制线性向导。结项面板只有一个写入入口；P1 将主入口移到「验收与结项」，旧「方案设计」入口保留跳转，不能出现两个独立表单。

| 一级分组 | 子页面与旧链接承接 | 首屏内容 |
|---|---|---|
| 概览 | 概览 `overview` | 项目代号、阶段、负责人；任务进度与门禁结果分别显示，下方突出当前用户可做的一步；没有个人待办则显示当前责任角色。保留客户目标和项目指引。 |
| 售前与商务 | 调研 `research`、方案设计 `delivery`、报价收款 `commercial` | 从已确认调研进入关联方案；显示当前选中方案的版本、商机/机会归属和报价前置。SOW 与报价对外件分别标名。 |
| 交付执行 | 任务 `tasks`、工作流 `workflow`、智能体 `agents`、执行事实 `facts` | 先显示我的任务/阻塞与到期；进入详情先看任务、依据和产物，再展开工具配置。 |
| 验收与结项 | 门禁 `gates`、评审会 `meetings`、结项交付包（独立视图或锚点，待开发确认最小路由） | 证据未齐、待核验、待裁定分列；结项展示候选、包清单、封存与登记回执。即使任务 100%，也不能推断门禁全部通过。 |
| 资料与设置 | 文件库 `library`、术语表 `ontology`、项目管理 `management` | 文档、文件及相应版本可追溯；成员与模块配置放在管理子页，权限不随移动而变。 |

项目页文本线框（宽窗）：

```text
项目列表 > 项目代号 / 项目名称                    项目状态 · 负责人
概览   售前与商务   交付执行   验收与结项   资料与设置
阶段门禁：待核验 1 项 | 任务：8 / 10 完成 | 交付包：未封存
下一步：核验上线材料 · 责任：项目负责人            [查看材料]
当前分组内容：队列 / 列表                 详情与原文（可收起）
```

实际「下一步」只来自授权的现有数据：有本人可执行事项优先显示；只能等他人时显示责任角色和可读进度；数据部分失败时说「暂无法核实」，不猜阻塞原因。没有可靠前置数据时直达对应模块，不在客户端造第二套业务判定。

## 5. Key Flows · 关键流程改进

### F1 售前交给项目负责人：记录 → 核对 → 形成可推进方案

1. 售前从项目调研进入指定对象；已有轻量录入、模板和 AI 起草则保留，不提前开放受门禁约束的材料上传。审阅页把原文锚点、AI 候选和人工修订放在同一上下文。
2. 售前确认自己有权处理的事实；保留来源、确认人和版本。负责人从回执直接打开在有效项目机会下的方案；候选不自动进入正式方案。
3. 负责人在报价动作旁看真实前置：首单回校（适用时）、成交或定稿条件、对外数字签字。不同动作按实际返回列条件，不把验收样例的 11 项当所有项目常量。**完成标记**：对应人工确认回执可查，SOW 和报价对外件各自按版本可找回。

### F2 负责人指派，工程师接单：可领 → 已接 → 可工作

1. 负责人在版本、发布前置和包状态齐备后按现有权限发布并指派。工程师直接进入「我的接单」，先看范围、有效期和授权可见的交付条件。
2. 工程师本人确认接单；提交期间仅禁用当前邀约提交。接口回执确认「已接单」后，回读原邀约/交接信息并验证项目可访问。**完成标记**：显示「已接单 · 项目已开放」及「进入项目任务」。
3. 若已接但交接未证实，显示「已接单，项目入口待核实」，只提供查状态/联系负责人，不再提交接单。过期、被他人处理、无权限各有独立反馈；网络超时先查结果，不盲重发。

### F3 工程师日常推进：定位任务 → 保存 → 转交下一位

1. 从「我的任务」进具体项目任务；行内改状态可继续用拖拽，但保留下拉/键盘等价路径。复杂编辑用详情；返回保留筛选、页码与焦点。
2. 并发冲突按字段展示原值、服务端最新值和草稿，只提交本人改动；双方改同一字段由本人选定，不自动覆盖，刷新失败不允许伪装成已恢复。无授权字段不发送。
3. 要补证据时从任务直达有权限的门禁项，保留项目和门禁上下文；候选目标不默认勾选。**完成标记**：任务最新状态回读，证据标为「已登记／待核验」，不等同门禁通过；显示下一位责任角色。

### F4 负责人会同管理员验收：核对原文 → 人工裁定 → 封存 → 登记

1. 门禁清单显示缺项、待核验和已核验。人工先逐项核对，再走现有裁定动作，不新增独立核验写接口。证据提交与裁定在服务端锁定同一门禁后比较确认时看到的 `revision`；证据提交成功后同步推进版本，旧确认不可沿用。冲突保留可用输入、清空旧核验选择，要求重核。AI 审阅沿用原文核对、历史裁定与 `superseded` 置灰。
2. 结项交付包按「已复核产物／已确认文档／可用文件」挑选；保持现有跨类型勾选。预览显示类型、版本、项数与指纹摘要，任一候选被服务端确认失效就标该行并保持其余选择。
3. 负责人按现有授权封存；管理员确认时看到包名、件数、封存时间和摘要。登记绑定用户看到的完整 `manifest_sha256` 和 `unsealed_count`；草稿编辑、封存、解封、登记使用同一包的锁定规则。**完成标记**：按回执或回读显示真实终态和封存摘要；回读不能证明本次写是谁提交的时，只报告包状态，不把它归到当前操作者。不宣称客户已签收，不触发自动付款或对外发送。

## 6. Component Patterns · 交互与反馈

| 组件／行为 | 落地约定 |
|---|---|
| 待办行与下一步区 | 同一行展示对象、状态、期限/责任人及一个主要动作。主按钮沿用 `{components.primary-action}`；「更多」承接低频动作，危险动作单独放置。列表和详情读同一对象，任一局部读失败不能抹掉其他已确认数据。 |
| 写入回执与重复提交 | 请求在途锁当前对象动作，不锁整页。可安全去重的动作复用既有幂等能力；结果未知时回读（或明确标记未知），禁止自动再发不可逆写请求。成功提示承载对象、结果及下一站。 |
| 批量工具条 | 显示「当前筛选 · 已加载 · 已选 N 条」，无选择不可执行。提交前预览具体范围与数量，切换筛选后清空当前批量选择或显式重确认；与封包的跨类型累计选择区分。部分成功分项回执，不悄悄重发已经处理的项。 |
| 表单、差异和留在原处 | 输入校验就地标注并将焦点移到首错字段；保留当前账号、当前会话内的草稿。离开有未保存提示；重新登录、换号或权限撤回不跨身份恢复草稿。密码、令牌、证据原文不写 URL、前端持久缓存或遥测。 |
| 高风险确认 | 登记交付、替换证据等显示对象、现状态、将变成什么、能否撤销；已要求的人/密码/备注/版本闸保持。普通保存不滥用弹窗；没有授权的用户不会因确认框而获得权限。 |

## 7. State Patterns · 状态与异常处理

| 情况 | 提示示例与动作 |
|---|---|
| 加载／空／筛选无结果 | 加载用「正在读取候选」，成功无结果才显示「暂无符合条件的交付件」；筛选为空给「清除筛选」，未具备条件时只在证实后显示「去确认文档版本」或「联系管理员发布模板」。 |
| 排队／执行／等待人工 | 「已排队，可关闭此页」仅对确有后台作业的入口使用；续看按对象及版本定位。人工等待显示负责人角色、期限（有数据时）和入口，不把已发起写成已完成。 |
| 409 业务前置未满足 | 「暂不能生成对外报价件：仍有数字待确认」→ 有权限时「去核对数字」；无权则指向责任角色。版本冲突另走差异处理，不一律给「重试」。 |
| 401／403／404 | 401 已无法续会话时请重登，合法深链可再进入。已知授权对象的能力不足可说「当前账号不能执行此操作」；需隐身的 404 一律使用不确认存在的文案，不附对象名或替用户申请权限。 |
| 超时／离线／部分失败 | 区分读取失败与写结果未知。前者原地「重新读取」，后者「查看提交结果」；不支持离线写入队列，不承诺回网自动同步。多源队列单独标明未加载分区，不把部分数据当完整。 |
| 成功／取消／失败 | 「已保存」「已提交，待核验」「已封存，待登记」分别使用可确认结果。取消只在服务端返回取消后显示；失败给可公开原因、下一步，可重试时才给重试按钮。 |

### Voice and Tone · 界面措辞

用「对象 + 发生了什么 + 下一步」，不暴露堆栈、内部路径或敏感字段。统一「派单包」与「结项交付包」、「登记证据」与「核验证据」、「封存」与「登记已交付」；AI 结果明确写「候选」或「建议」。状态标签采用 `{colors.success-text}`、`{colors.warning-text}` 等语义令牌，不能只凭颜色看结论。

### Interaction Primitives / Accessibility Floor

- 页面层级固定：侧栏 → 项目分组 → 当前对象。连接、标签和按钮各用正确语义；链接可复制时只带合法的对象定位和视图参数；无敏感值。返回焦点落在原对象，状态变化不抢焦点。
- `Tab` 顺序按阅读和操作顺序，`Esc` 关闭最上层对话框并恢复触发处焦点，确认框内可用键盘完成取消或提交。快捷保存沿用已有 `Ctrl+S`，表格改状态不能只支持拖拽；错误和完成通过适当的 `aria-live` 通知。
- 普通文字对比 ≥4.5:1，大号文字和必需非文字控件 ≥3:1。先用 1366×768、1024×768（或应用实际最小可用窗体）及 125%/150% 缩放验主路径；较窄时详情转单列，不横滑整页，不允许底栏遮住按钮和焦点。颜色、图标、文字并用；承接系统减少动效设置。

## 8. 验收标准与落地顺序

**发布策略（2026-11-18 蔡工拍板）：受控迁移后严格。** 先盘点桌面、网页和操作脚本的实际调用，联调验证条件写并确定切换窗口；迁移期不算 P0 销项。切严格后，未升级端保留原有授权读取，但交付登记、门禁证据提交和裁定缺少确认条件时一律拒绝。新端须依据明确的服务端契约能力判断是否可以提交，不能把旧服务端已有的 `revision` 或摘要当成保护已生效。服务端若必须回退到无保护的版本，先暂停这三项写操作；不开放无条件写入作为旁路。详见 [Party Mode 第二轮纪要](./PartyMode第二轮评审-2026-11-18.md)。

以下均为**待实施的验收**。以合成项目和角色账号测试，不在真实项目复演写路径。A01–A13 为行为断言，不是当前版本已通过的测试。A03、A05、A12 的并发断言须用隔离的 PostgreSQL 双连接验证，既测顺序变更后的旧确认，也测事务真正重叠；界面 mock 不替代数据库锁实证。

| 编号 | 验收标准（可执行） |
|---|---|
| A01 并发编辑 | A 打开任务；B 改截止日并保存；A 只改进度遇冲突后完成合并，B 的截止日不变。两人同改进度时，未选择冲突解决方案不能提交；刷新失败保留草稿和提示，不改版本、不自动写。 |
| A02 批量范围 | 3 条待审、仅 1 条符合当前筛选；勾选该条并确认，只对该 ID 发写请求，隐藏两条零变化。模拟部分失败，成功项消失/更新，失败项就地可核对，不重发成功项。 |
| A03 门禁证据 | 未选目标无提交，替换可见旧、新摘要和待核验影响，取消零写入。两会话分别验证空项被先填、旧证据被先换、同指纹但人工状态或提交人改变；旧确认不能改清单、落证据行、剪除候选或写成功事件。采纳不自动核验或判门。 |
| A04 空与失败 | 封包列表及任一类型的候选接口模拟 5xx、断网、200 空结果；三者展示可区分。重试可以只刷新失败分区；跨类型已选内容不丢，失效项不能提交。 |
| A05 终态确认 | 无权限仍由后端拒绝，授权用户取消零写入。同一清单解封重封后，旧确认拒绝且不写登记事件；登记与解封并发结果一致，两次登记并发最多一条成功事件。结果未知先回读，不自动重发；终态无解封或重复登记入口。 |
| A06 接单回执 | 任务中心到「我的接单」≤1 次导航；接受且已获项目访问时，回执到项目任务≤1 次导航。过期或并发更新不得出现成功；接单已确认而交接未确认时，只能读状态，不能重复接单。 |
| A07 导航兼容 | 旧项目标签、方案/机会参数、旧结项入口和 `#dispatch/mine` 可到相同业务对象；项目列表返回保留筛选、页码与焦点。切换账号清除上个账号的本地筛选/上下文；不能借深链越权。 |
| A08 异步作业 | 同一 SOW 作业关闭页面后按版本找回；「失败」「取消」「查询失败」三者文案与动作不同。模拟后台执行中查询失败，页面不得把作业标成失败或自动创建新作业。 |
| A09 前置分流 | 对未回校报价、字段未确认、未确认文档和模板不可用分别验证原因及修复去向；未掌握证据时只报「无法核实」。每种负例均不放宽原服务端闸。 |
| A10 授权与无障碍 | 用四类核心业务角色和一只读账号分别走授权路径；补无授权同企业/跨企业及权限撤回负例，队列、计数、详细页无泄露且同义。键盘可达、焦点可见，缩放下动作不被遮挡；向导无强制拖拽。 |
| A11 看板回真 | 两张任务卡并发保存，一张触发 409、另一张仍在途；正确回滚冲突卡，在途结束后补读，只有回读成功才显示「已刷新」。模拟补读失败，界面给就地重试并保留最后已知状态。 |
| A12 旧裁定失效 | A 打开裁定，B 按现有权限更新证据；A 以旧版本提交时拒绝，不核验新证据、不判门、不写成功事件。重新打开并核对后，符合原职责分离与判门规则的裁定可继续。 |
| A13 切换与回退 | 覆盖新旧客户端和新旧服务端组合。新端无法确认服务端支持条件写时不发送；切严格后授权旧端保留读取，但无确认条件的三项写入被拒绝并给出升级指引。未授权仍按原口径返回，不泄露快照。回退导致保护失效前，先暂停相关写入。 |
