# 系统意图：定时与后台任务

> 容器侧后台 + 宿主侧计划任务的运维地图（goal-r3 G2，2026-10-30；**快照更新 2026-11-07 架构评估修复轮**——scheduler 面 1→5、worker job 类型 8→12 现测校正）。改 `server/` 后必须 `docker compose build && up -d`（代码烤进镜像）。

## 容器侧（compose.yaml）

| 服务 | 入口 | 判活 | 语义 |
|---|---|---|---|
| worker | `flask worker`（compose.yaml:65；循环见 cli.py:147-182） | Redis 心跳键 `fde:health:worker` TTL 180s（heartbeat.py:30） | 消费 Redis list `fde-jobs`（FIFO）；单活租约 5min `(job_type,target_id)` 守卫（jobs/queue.py:51）；终态重放 no-op |
| scheduler | `flask scheduler`（compose.yaml:101；cli.py:213-260，默认 30s 轮） | 心跳 `fde:health:scheduler` TTL 900s（heartbeat.py:31） | 每轮 `dispatch_due_automations()`：扫 `automation_tasks` 到期行 |
| api | gunicorn（端口仅绑 127.0.0.1:8010） | `/api/v1/health/ready` 真校验 DB+Redis | — |

**scheduler 周期任务面（2026-11-07 现测 5 个，原文「唯一 1 个」已失效）**：①`dispatch_due_automations`（`control/scheduler.py:62`）——`SELECT … FOR UPDATE SKIP_LOCKED` 取到期行 → 每条插入 `automation_task_runs`（幂等键 `schedule:{task_id}:{scheduled_for}` 唯一约束去重，models.py:133）→ `enqueue_outbox("automation.execute")` → 推进 next_run_at。schedule_kind：once / interval(`Nm/Nh/Nd`) / calendar(5 段 cron，逐分钟前推 ≤2 年) / event(不调度)（scheduler.py:17-59）。②`sweep_expired_approvals`（T-P1-5，scheduler.py:97）③`remind_pending_approvals`（B#5 退避 10m→24h，scheduler.py:133）④`schedule_expired_upload_cleanup`（B#13-B UploadSession 到期，cli.py:244）⑤`dispatch.maintenance` 24h 节流补投（goal-r6，cli.py:249-259）。**无预调研/翻译类自动定时**——两者全由 HTTP 触发入队。

**worker job 类型（2026-11-07 现测 12 个，原文 8 个已滞后）**（`jobs/handlers.py:42-92`）：file.scan / file.preview / **file.upload.cleanup**（B#13-B）/ document.generate / project.presurvey.analyze / research.export / automation.execute / ai.chat / ai.execute / **dispatch.maintenance**（goal-r6）/ **translator.translate**（goal-d9）/ **workflow.run**（T-W3 执行器）。事件先落 `outbox_events` 再入队（outbox 模式；终态闭环 `jobs/outbox.py`——`mark_completed`/`mark_failed` 只收 dispatched、`cancel_for_job` 一并收口，T-J1）。

## 宿主侧：FDE-Bridge-Poll（Windows 计划任务）

| 项 | 事实 | 出处 |
|---|---|---|
| 周期 | 每 4 小时（2026-10-25 用户裁决，原 15min）；StartWhenAvailable 错过补跑，限时 10min | `scripts/install-bridge-poll-task.ps1:11-16` |
| 动作 | `wscript //B` 隐藏跑 `run-bridge-poll.vbs` → `node bridge-poll.mjs >> logs\bridge-poll.log`（>1MB 自轮转） | vbs:13-26 |
| 采集 | openfde 只读 CLI 白名单 + fdeops 文件探针 → `POST /api/v1/bridge/snapshots`（Bearer FDE_BRIDGE_TOKEN） | bridge-poll.mjs:98-135 |
| 手动触发 | `schtasks //Run //TN "FDE-Bridge-Poll"`（Git Bash 双斜杠）或桌面「立即采集」（同一命令，`desktop/src/main/bridge-capture.ts:42`） | — |
| `--check` | 快照含 orphan 项目指针 → 退出码 2（§1 铁律巡检）；常规失败 1 | bridge-poll.mjs:18-20 |

**纪律**：采集器只读（绝不写真相层）；只能跑在 Windows 宿主（openfde CLI 是 Win 版 Node 工具，容器内 subprocess 不到）。

## 独立进程（不在 compose 内）

`python -m fde_api.control.weixin_worker`：微信收发循环，inbox-before-cursor 防丢消息（weixin_worker.py:1-8）。另有宿主采集器 runbook 技能 `.agents/skills/fde-bridge-capture/`。

**无其他定时面**：n8n 桥接（`QFhunterFeed01` 等）属 somwyn 管道侧，在仓库外，本仓库零代码耦合（grep 全仓仅历史文档提及）。
