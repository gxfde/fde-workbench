### 核心内容

**F2-1 命名法（沿用既有约定，不另立一套）**

| 类别 | 格式 | 例 |
|---|---|---|
| 矢量资产 | `caigong-fde-<用途>.svg` | `caigong-fde-logo-master.svg` |
| 位图/图标 | `caigong-fde-<用途>-<尺寸>.png` | `app-icon-1024.png`（既有命名，保留不强行改名） |
| 规范文档 | `BRAND-<主题>.md` / `specs/<组>-<主题>补齐.md` | `BRAND-COLOR-SPEC.md` |
| 成品交付件 | `蔡工FDE-<文档名>.<pdf/pptx>` | `蔡工FDE-品牌手册.pdf` |
| 模板 | `caigong-fde-<用途>-template.<ext>` | `caigong-fde-ppt-template.pptx` |
| 脚本 | `build_<用途>.py` / `make_<用途>.mjs` | `build_logo_svgs.py` |
| 备份 | `_backup-<场景>/` | `_backup-pre-brand/` |

> 命名规则：**小写连字符、不含空格、不含中文路径段（成品交付件除外）；既有文件名不因规范升级而批量重命名**，避免打断 `AppShell.tsx`、`index.html`、脚本里的既有引用。

**F2-2 源文件 / 生成物标记（关键，防止改错对象）**

| 类型 | 判定 | 修改方式 |
|---|---|---|
| **单一真源** | `build_logo_svgs.py` 的几何/色值参数、`BRAND-LOGO-GUIDE.md` 的定稿话术、`BRAND-COLOR-SPEC.md` 的色值、`server/seeds/gates.json` 的门禁名 | 只改这里，改后重跑生成器全套同步 |
| **生成物** | 8 个 SVG、PNG/ICO、名片 SVG、`assets/hdr-mark-*.png`、17 个 docx 模板（`brandize-document-templates.py` 产物） | **禁止手改**；改真源后重跑脚本 |
| **手工文档** | 本目录所有 `*.md`、`assets/email-signature.html` | 直接编辑，须留 CHANGELOG |
| **成品** | `deliverables/*.pdf` / `*.pptx` | 由内容源重新导出，不直接改成品 |

> ⚠️ **已知覆盖风险（来自 D1）**：`scripts/build-document-templates.py` 重建会抹掉 17 个 docx 的品牌化页眉页脚；重建后**必须重跑** `scripts/brandize-document-templates.py`。合并入 build 的方案待确认⑥，未立项前按此双脚本流程执行。

**F2-3 版本与变更记录**

- 每份规范文档头部必须含：版本、编制/修订日期、状态、上位文档、待确认项。
- 新建 `BRAND-CHANGELOG.md`（本次产出）记录：`日期 ｜ 版本 ｜ 变更文件 ｜ 变更内容 ｜ 原因 ｜ 执行人（待确认①） ｜ 影响的下游物料`。
- 色值、几何、定稿话术、门禁名称任一变更 → 视为**破坏性变更**：须同步 SVG 全套、桌面端 tokens、官网、名片、docx 模板、PDF/PPTX 成品，并在 F3 巡检表中标「本季度需复查」。
- 版本子目录策略待确认③；未落定前不新建 `v1.0/` 目录，仅以 CHANGELOG + 文档头版本标记。

**F2-4 备份规则**：批量改写前先整目录备份到 `_backup-<场景>/`，确认成功后再执行；备份目录不参与对外分发，也不计入交付件。
